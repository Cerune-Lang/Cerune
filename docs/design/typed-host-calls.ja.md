# JS/TSからの型付き関数呼出し

[English](typed-host-calls.en.md)

[#161](https://github.com/Cerune-Lang/Cerune/issues/161)の比較設計です。**最初の製品実装は生成WATの関数公開を推奨します。** 今回追加したのは固定関数による実験であり、任意の関数を公開するAPI・CLIは未実装です。通常の実行入口は引き続きIR Executorです。

## 現在あるもの

調査対象はCeruneの `e0d7270` と、[Tint*のWasm wrapper](https://github.com/Cerune-Lang/Tint-St/blob/ddb676a6d24c6a628203b9cabb877462b5fc01a4/experiments/wasm/src/lib.rs)です。Tintのコードは変更していません。

| 経路 | 実装済み | 今回の目的に足りないもの |
| --- | --- | --- |
| [VM埋め込み](vm-embedding.ja.md) | `embedding::resolve_function`でbytecodeと結び付いた関数を保持し、`invoke_function`で反復実行。引数はf64、戻り値はf64/void、出力と停止位置を取得 | JS/TS向け公開、他のホスト値型、利用者向け公開宣言の一覧 |
| IR Executor | 完成IRの直接実行、入力・出力・診断 | 名前付き関数を型付き引数で呼ぶ公開API |
| Tint* | ソースの検査・各表現の生成・IR/MIR/VM実行 | 現在の `execute(source, path)` は毎回コンパイルして出力文字列を返す。コンパイル済み関数を繰り返すJS APIはない |
| WAT | Cerune関数をWasm関数へ変換。`main`をexport、内部memoryは非公開 | 任意の公開関数選択、外部用型変換、検査付きJSとTS宣言 |

VM埋め込みを新設する必要はありません。既存APIは呼出しごとに独立した実行状態を作り、トップレベル文やmainを実行しません。I/Oを含む関数も扱うため、純粋関数だけを受け付ける検査ではありません。失敗後の別呼出しも可能です。

## 同じ関数による比較

[通常のCerune例](../../examples/host_calls/README.md)と[実験の手順](../../experiments/host_calls/README.md)を分けました。関数 `step(position, velocity, delta)`、失敗する変換、i32/u64/f32の受渡しを確認します。

| 比較項目 | VMをWasm化 | 生成WAT |
| --- | --- | --- |
| 準備 | Rustの処理系と固定ソースを同梱し、一度だけコンパイル・関数解決 | 同じソースから事前生成したWATを外部wabtでWasm化 |
| 反復呼出し | 既存VM埋め込みAPIへ渡す | 生成された関数へ直接渡す |
| 共通確認 | f64結果、引数の数・型、NaN、停止理由とNodeId/SourceId/Span、新しいインスタンスでの再実行 | 同左 |
| 追加確認 | Rust APIのf64契約を再利用 | i32の幅変換、u64のBigInt範囲、f32の丸め、memory非公開、必要import |
| 実験の制約 | 固定ソース・関数だけ。Rust Wasm自体にはmemory exportがあるがJSアダプターには渡さない | 出力WATへ固定wrapperを追加。製品emitterの公開APIではない |

2026-10-18、Node 20.20.2、x86-64での一回の測定です。Linux/WSLはWindowsで作った同じWasmバイナリを使用しました。

| 指標 | VM Wasm | 生成WATのWasm |
| --- | ---: | ---: |
| バイナリのバイト数 | 979,282 | 3,180 |
| Windowsの10,000呼出し | 12.71 ms | 1.88 ms |
| Linux/WSLの10,000呼出し | 11.71 ms | 2.63 ms |
| Windowsのソース準備 | 21.59 ms | 事前生成のため測定外 |
| Linux/WSLのソース準備 | 22.87 ms | 事前生成のため測定外 |

1,000回の準備呼出し後、JSの引数検査・結果確認込みで測定しています。Wasm自体のcompile/instantiateは別に記録します。生成WAT側のソースコンパイル・assembly時間は上表に含みません。処理系を同梱する経路と事前コンパイルする経路の、この小さな例での比較です。一般的な速度、ブラウザーの起動時間、Cisa/Stelleの実性能を保証せず、CIにも速度の合否閾値を設けません。

## 最初の製品実装案

アプリのロジックを事前に生成し反復利用する用途では、コンパイラを配布先へ含めなくてよいWAT公開を先に進めます。VMはソースをその場で変更する用途に適し、今回も独立した比較相手になります。両方の意味論を新しく実装しません。

| 項目 | 初版の提案 |
| --- | --- |
| 公開対象 | 入口モジュールの名前付き・非genericなpub関数から明示選択。pubだけではWasm exportにならない |
| 宣言情報 | frontendが公開名・型・出自とIR関数の対応を保持。内部FunctionIdや `module_N_` の名前から公開範囲を推測しない |
| ライブラリの初期化 | トップレベル実行文とmainを受け付けない。instantiateで利用者コードを暗黙実行しない |
| 初版の値と処理 | 公開引数・戻り値はi32/f64。本文はスカラー計算・局所変数更新・分岐・反復・関数呼出し。I/O、ヒープ確保、複合値を含むライブラリは診断する |
| 検査範囲 | 最初はライブラリ全体を保守的に検査。未使用関数を黙って除去して適合したことにしない。privateな補助関数も同じ条件を確認する |
| 生成物 | WAT、公開名・型・出自・契約版の一覧、検査付きJS、TS宣言。CLI/APIの具体名は実装時に確定 |
| 状態 | 同一インスタンスで同期・逐次呼出し。状態共有、再入、並行呼出しは初版で提供しない |
| 失敗後 | 言語上の停止・trap・実行中のhost例外の後はそのJSハンドルを閉じる。引数検査失敗では実行していないので閉じない |
| 権限 | DOM・ネットワーク・任意host callbackを暗黙に接続しない。診断の出力先を明示する |

これは**最初のホストAPIが受け付ける範囲**であり、通常のCeruneプログラムや他経路の対応機能を狭める変更ではありません。文字列・配列・構造体・enum・所有権は後続設計です。スカラー関数でも変換失敗や桁あふれは起こり、反復が終了する保証もありません。

現在のモジュール解決ではpubを検査しますが、完成IRの関数にはその公開情報が残りません。次の実装では宣言情報を解決時に保持し、IRへ変換した後も公開元と対応付けます。

### 型の受渡し

内部WATではi32を含むCerune整数がi64です。その関数をそのまま公開するとJSからもBigIntが必要になります。外部用wrapperでCeruneの型とWasm ABIを対応付けます。

| Cerune型 | JS値と検査 | Wasmでの受渡し |
| --- | --- | --- |
| f64 | Numberのみ。NaN/Infinity/-0を許す。文字列等の暗黙変換をしない | f64 |
| i32 | Numberの整数かつ範囲内。-0は符号を黙って落とさず拒否 | 外部i32を内部i64へ符号拡張。結果をi32へ戻す |
| u64（後続候補、実験のみ） | 0〜2^64−1のBigInt | i64のビット列。戻り値の符号を明示的に復元 |
| f32（後続候補、raw実験のみ） | 丸めを許すAPIか、正確に表せるNumberだけにするか未決 | f32の丸めを確認。f64の契約へ混ぜない |

[WebAssembly JS API](https://webassembly.github.io/spec/js-api/)の生の呼出しは引数を変換します。実験では小数の切捨て、整数の折返し、省略引数のNaNを確認しました。TS宣言だけでは実行時の値を検査できないため、JS側でも引数の数・型・範囲を検査します。f64の演算ごとの丸めは[既存の浮動小数点契約](float-rounding.ja.md)を変更しません。

### 失敗と観測

製品APIではコンパイル、公開対象の解決、instantiate、引数検査、言語上の停止、Wasm trap、host例外を区別します。言語上の停止は既存の `runtime-v1` とNodeId/SourceId/Spanを保持します。trapを根拠なしにCeruneの停止理由へ変換しません。

実験のJSアダプターは呼出し時の `arguments/language/trap/host/closed` を分けます。compile/instantiate失敗はまだ標準JS例外のままです。VMは失敗記録を別に取得するため、正常なNaNと失敗を混同しません。実験アダプターの「失敗後は閉じる」はWATの破棄方針に合わせた方針で、既存Rust VM APIの失敗後の再利用を変更しません。

元のIR、bytecode、通常のWAT、wrapper追加後のWAT、停止記録を保存します。公開宣言・wrapper・型変換を観測できるようにし、観測APIが呼出しや状態変更を起こす形にはしません。完成IRや通常の非最適化出力は残します。WATはemit-onlyであり、外部assembly以降を新しいbuild/release責務には含めません。

## 実装順と未対応

1. **今回完了**：現状調査、固定関数のA/B比較、通常例、TS型検査、日英設計、CIで結果・停止・生成物を比較。
2. **次**：公開宣言の一覧と出自をfrontendから保持し、明示選択・ライブラリ検査・WAT wrapperを製品APIとして実装。
3. 検査付きJSとTS宣言の生成、誤った入力・停止・再利用の回帰テスト、HTMLから繰り返し呼ぶ例とブラウザーでの確認。
4. 実用途を見て追加スカラー型、IR/VMのJS公開、複合値・所有の契約を検討。

固定関数の内部名検索、WAT文字列への追記、手書きTS宣言は今回の実験専用です。製品APIでこれらを一般化して使うことはありません。汎用FFI、JS backend、一般パッケージ管理、新しいsandbox、全処理系の正しさの証明は今回の対象外です。
