# 可観測性の契約

[English](observability.en.md)

## 目的

この文書では、Ceruneが元のソースの文・式とIR、MIR、生成コードの対応をどう表示・記録するか、観測用APIから何を変更できないかを説明します。

コンパイル結果を調べる情報は提供しますが、その情報を使って型検査結果や生成する命令を書き換える機能は提供しません。

## 観測と制御の分離

- 観測用APIは、コンパイル中の型情報・IR・命令選択結果を読み取るための情報を返します。返した情報を使ってそれらを変更する操作は設けません。
- 外部コードからコンパイラ内部のIR命令や型検査結果を直接書き換えるAPIは設けません。
- 将来、コンパイル中の処理を差し替えるプラグインやフックを用意する場合は、IRを表示するAPIとは別に、その操作と利用条件を定義します。
- 観測結果に含まれる`NodeId`などの番号を指定しても、コンパイラ内部の命令を削除・差し替えできるわけではありません。

## 内部可観測性

- トークン、AST、意味解析結果、IRで、どのソースの位置に由来するかを記録し、各段階で文や式を辿れるようにします。
- Cerune IRの文と式には、一回のコンパイル内で一意な決定的`NodeId`を付けます。`NodeId`とソース位置を表す`Span`は区別します。
- 構文要素にはソースの開始・終了位置を保持します。bytecodeの各命令には、元のCerune IRの`NodeId`と診断に使う`Span`、またはコンパイラが追加した命令であることを示す情報を付けます。
- `Synthetic`はコンパイラが意図して追加した処理を示します。元の`NodeId`や`Span`を途中で失った処理の代わりに`Synthetic`を付けません。
- 観測用APIは、コンパイラ内部で変更されるデータそのものではなく、表示・検査用に取り出した情報を返します。
- 観測用に取り出した情報を型検査や命令選択へ戻して、生成結果を変える処理は行いません。

## 公開観測面

- 現在は`emit-ir`でCerune IR（HIR）、`emit-mir`でMIR、各種`emit-*`でC・LLVM IR・QBE IR・WAT・ASM・Objectなどの生成結果を確認できます。
- Cerune IRのテキスト表現は、文と式の`NodeId`を`#N`として公開します。
- `emit-mir`の`Cerune MIR v0.1`には、型、式の評価順、所有操作、分岐、元のソース位置との対応が表示されます。このテキストをそのまま配布して読み込み・実行する機能はありません。MIRのblock番号・命令番号とHIRの`NodeId`は、同じ番号でも別の要素を指します。
- コンパイラ内部に保存したすべての情報を外部APIで読めるとは限りません。また、内部の情報の持ち方が今後の版でも同じであることは保証しません。
- 新しい観測用の出力形式を公開するときは、形式のバージョンと各項目の意味を文書化します。

## セキュリティ

- ソース本文やファイルパスは、利用者が明示的に要求した場合にのみ開示します。
- 端末へ診断やソース断片を表示するときは、含まれる制御文字やエスケープシーケンスが意図しない端末操作にならないよう処理します。
- トレースの項目数、診断メッセージの長さ、表示するソース断片の長さには上限を設けます。
- 観測結果に環境変数の一覧、秘密鍵やトークン、コンパイル結果の確認に不要な実行環境の情報を自動で含めません。

## 再現性

- `--annotate-origins`などで元ソースとの対応を示すコメントやシンボルを追加しても、生成した命令の動作やプログラムの実行結果は変えません。注釈付きと注釈なしでは、コメントやObjectのシンボル表が異なる場合があります。
- Ceruneのバージョン、ソース、出力経路、ターゲット、使用するCPU機能、明示したオプションがすべて同じなら、同じ観測結果を生成します。
- `NodeId`はこの条件の下で決定的ですが、ソース編集やCeruneのバージョン変更をまたぐ永続IDではありません。
- 観測結果に、実行時刻や毎回変わるランダムな識別子を自動で挿入しません。

## LLVMの出自注釈

[登録済みファイルのAPI](source-files.ja.md)では、LLVM・ASMともに`#N`と`bytes`の間に`file=N`を加えます。範囲はそのファイル内のバイト位置です。従来の単一ソースAPIとCLIではこのフィールドを省略します。

`emit-llvm --annotate-origins`は、既存のLLVM成果物に読み取り専用のコメントを加えます。形式は`; cerune-origins v1`で識別します。

```llvm
; cerune-origin: #7 bytes 208..235
  %tmp2 = call i1 @cerune.string.equal(%cerune.string %tmp1, %cerune.string { ptr @cerune.string.1, i64 10 })
```

これはLFで保存した`examples/string_origins.ceru`の`echo(left) == "日本語\0"`に対応します。`emit-ir`の`#7 eq.string(...)`から同じ比較へ辿れます。範囲は元の入力のUTF-8バイト位置で、終端を含みません。CRLFの入力ではその分だけ位置が変わります。

Lowererは命令ごとに`Source { NodeId, Span }`または`Synthetic`を記録します。例えば比較式の左辺・右辺を命令へ変換した後、比較命令には比較式自身の`NodeId`と`Span`を付けます。これにより、比較・出力・短絡評価の分岐を、子の式と取り違えません。Emitterは記録済みのバックエンドIRを使って出力します。

注釈は次の注釈までの命令群に適用します。一つのCerune式から複数命令が生まれる場合があり、命令を生成しないリテラルなどは個別の注釈を持ちません。モジュールの定数配置、共通補助関数、スタック領域、引数の保存、起動処理は`synthetic`です。これは生成された処理だと明示するもので、ソース位置を失った状態の代用ではありません。利用箇所の命令から出自を追います。外部コンパイラによる最適化後の対応やデバッグ情報は保証しません。

注釈にはソース本文・パスを含めません。注釈の有無はloweringに入力せず、出力時のコメント追加だけを切り替えます。注釈を除いたLLVMは通常出力と一致し、実行結果も同じであることをexampleで検証します。

LLVMの`cerune-origin`コメントは、生成した命令から元の`NodeId`を調べるための情報です。このコメントを使ってコンパイラ内部のIRを書き換えるAPIはありません。IRと注釈付きLLVMの対は`tests/fixtures/observation/string-origins/expected/`に固定しています。

## ASMと機械語の出自

`emit-asm --annotate-origins`もNodeIdとUTF-8バイト範囲を保持します。コメントと`cerune_origin_nN_...`ラベルを加え、オブジェクトのシンボル・逆アセンブルからIRへ辿れます。両ターゲットのIR/ASMの対は`tests/fixtures/observation/native-values/expected/`に固定しています。注釈を除いたASMの一致と、注釈の有無による命令バイトの一致をテストします。

Nativeは[HIR→MIR→LIR→ASM/Object](native-mir.ja.md)の順で変換します。注釈付きASMには`# cerune-mir: v1`の対応情報、Objectには`cerune_origin_mir_...`シンボルも残します。一つのMIR操作から複数のLIR命令が生まれ、LIRの検査・ABI処理はさらにASM命令へ展開されるため、命令数は一対一ではありません。ソースの式から作った命令、意味上必要な検査から作った命令、スタックの準備などコンパイラが追加した命令を区別して記録します。

機械語は[Sashimiを使うObject生成](native-encoder.ja.md)または外部アセンブラによるASMの組み立てで作ります。リンクは明示した外部ツールで行います。Objectを生成できたか、想定した理由で停止したか、正常終了したか、予期しない失敗が起きたかを別々に記録します。出自の範囲とアドレスの意味、実行手順は[ASMから機械語までを辿る](native-code.ja.md)を参照してください。
