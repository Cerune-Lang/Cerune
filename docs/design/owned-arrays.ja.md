# 所有する動的配列と範囲コピー

[English](owned-arrays.en.md)

**`[T]`・`array_copy`・`array_copy_range`・`array_repeat`・配列用予算は共通IR・IR Executor／VM・生成C・LLVM・QBE・WAT・Windows/Linux ASM・自前COFF/ELFで実装済みです。** 実行例は[動的配列のコピー](../../examples/dynamic_arrays/copy.ceru)と[入れ子・関数・enum](../../examples/dynamic_arrays/nested.ceru)です。[実装済みの文字列管理](dynamic-data.ja.md)を土台にしますが、更新できる配列の領域は独立してコピーします。

## 実装の進捗

| 段階 | 状態 |
| --- | --- |
| 引数の所有受け渡し | 実装済み。呼び出し側が準備した所有を一度だけ渡し、calleeが解放。IRで所有と内部の読み取りを区別 |
| 読み取りと所有値の準備 | 実装済み。共通IRの`read`束縛で読み取りを区別し、一時値の抽出と解放順を維持 |
| 動的配列の型・領域確保・独立コピー | IR・VM・C・LLVM・QBE・WAT・ASM・自前Objectで実装済み。範囲コピー、表示・比較・反復、複合値と関数も対応 |
| `array_repeat::<T>` | 実装済み。実行時の個数から独立したコピーを作り、共通IRの確保・ループ・解放へ展開 |
| 各生成経路の動的配列対応・下記の完了条件 | C・LLVM・QBE・WAT・Windows/Linux ASM・自前COFF/ELF対応済み |

全経路で動的配列も結果・停止理由・ソース位置・先行出力を照合しています。[呼び出し境界の所有](dynamic-data.ja.md#呼び出し境界の所有)と[読み取りの設計](dynamic-data.ja.md#読み取りと所有値の準備)、[引数](../../examples/owned_arguments.ceru)・[読み取り](../../examples/borrowed_reads.ceru)のexampleを参照してください。

## 型と最初の操作

| 表記・操作 | 意味 |
| --- | --- |
| `[T]` | 実行時の長さを持つ、所有する配列。長さは型の一部ではない |
| `[T; N]` | 従来の固定長配列。既存の構文と意味を維持 |
| `array_copy(values)` | 固定長・動的配列から同じ要素型の新しい`[T]`を作る |
| `array_copy_range(values, start, end)` | 半開区間`[start, end)`を新しい`[T]`へコピー |
| `array_repeat::<T>(value, count)` | 一度評価した値の独立したコピーを`count`個持つ配列 |
| `array_len(values)` | 固定長・動的配列の要素数を`i64`で返す |
| `values[index]` | `i64`の添字で参照。`mut`な束縛の配列は要素を更新できる |

実装した操作名は既存の`array_len`に揃えています。既存exampleのユーザー関数`copy_range`・`append`を予約語化しません。`array_copy`・`array_copy_range`・`array_repeat`との定義名の衝突は診断します。

固定長配列と動的配列の間に暗黙変換は設けません。配列リテラル`[1, 2]`は従来どおり固定長です。初回は動的配列リテラルを追加せず、空値は空範囲から作れます。`array_repeat::<T>(seed, 0)`でも作れますが、seedは要素数0でも評価します。`[T; 0]`・空リテラルの現在の制限は別の変更にしません。

以下は全経路で実行できます。

```text
mut values: [i64] = array_copy([10, 20, 30]);
saved: [i64] = values;
part: [i64] = array_copy_range(values, 1, 3);
values[1] = 99;
print(saved); // [10, 20, 30]
print(part);  // [20, 30]
empty: [i64] = array_copy_range(values, 3, 3);
print(empty); // []
```

等値比較は同じ要素型の動的配列同士で、長さと対応する要素を比較します。固定長配列との比較には明示コピーを要求し、順序比較は追加しません。表示は`[要素, ...]`、空なら`[]`とし、入れ子の文字列の引用規則も既存どおりです。`for … in`は長さ0なら本体を実行しません。

長さは`0..=i64::MAX`、初回の容量は常に長さと同じにします。異なる長さの同じ`[T]`を再代入できます。append、reserve、容量の公開、成長率、借用スライスは後続の設計です。

## 値コピーと観察を分ける

| 場面 | 生成する処理 |
| --- | --- |
| `b = a`、束縛の初期化、配列・構造体・enumへの格納 | 既存の値から、入れ子の動的配列も独立してコピーする |
| 関数の引数・返却 | 値渡し。既存値を渡す境界でコピーし、受け取った関数・呼び出し元が所有する |
| 新しく作った一時値を格納・引数・返却へ渡す | 一時値の所有を渡す。不要な二重コピーは作らない |
| `array_len(a)`、表示、等値比較、添字・フィールドの途中の参照 | 読み取りのために配列全体をコピーしない。対象を一度評価し、必要な間だけ生存させる |
| `for (item: T in values)` | 開始時に対象の独立したスナップショットを作り、各要素も値として渡す |
| `a[i] = value` | コピー先の該当要素だけを更新する。新しい要素の準備後に旧要素を解放 |
| 自己代入`a = a` | コピーを完了してから旧値を解放。旧値と新値が同時に予算へ計上される |

「最後に使う束縛だから」という理由でコピーを移動へ変えません。確保の失敗・予算・出自が変わるためです。一時値の所有移動と束縛の値コピーをIRで区別します。copy-on-writeも初回は使いません。

固定長配列・構造体の内部に`[T]`を含む場合も、この規則を再帰的に適用します。enumは選択中のペイロードだけをコピー・解放します。文字列の不変内容は共有し、文字列の参照保持・解放を生成します。`array_repeat`の各要素内の動的配列も独立し、一つの要素への更新が他へ伝わりません。

引数は左から順に、評価と必要な値コピーを完了してから次の引数へ進みます。引数コピーに失敗したら後続引数を評価しません。引数のために作った所有値をcalleeへ一度渡し、関数入口でさらにコピーはしません。束縛からのreturnでは戻り値コピーを完了してから局所値と引数を解放します。

matchは対象を一度所有値として保存し、選択したペイロードの束縛を値としてコピーします。ガードがfalseなら、その腕の束縛を解放してから次の腕へ進みます。構造体の既定値と更新式も既存の評価順を維持し、上書きする旧フィールドを新値の準備後に解放します。

読み取り操作が内部で対象を借りても、外部から使える参照型や共有可変APIは追加しません。たとえば`array_len(make())`ではmakeを実行し、その結果の所有値を読み取り後に解放します。表示・比較のオペランドは両方とも元の順で評価し、比較の要素走査だけを短絡できます。

## 範囲、更新、失敗の順序

`array_copy_range`では対象・開始・終了を左から一度ずつ評価します。対象はコピー元として読み取り、先に全体の動的コピーを作ることはしません。既存の値を指す対象も、一時値の対象も、操作が終わるまで生存させます。

1. 三つの引数の評価が成功してから、`0 <= start <= end <= array_len(values)`を検査する。
2. 検査後に`end - start`、管理上のサイズ、ターゲットでの配置サイズを計算・検査する。
3. 結果領域を確保し、元の添字の昇順に要素をコピーする。
4. 結果の所有を渡し、一時的なコピー元を解放する。

開始値が負でも、開始式自体が成功したなら終了式は評価します。終了式が停止すれば、その停止が範囲診断より先です。空範囲`[0, 0)`や`[length, length)`は有効で、結果用の要素領域を確保しません。

`array_repeat::<T>(value, count)`は要素型`T`を明示し、valueの型を`T`、countの型を`i64`に揃えます。型の推論や他の整数型からの暗黙変換はしません。

1. valueをコピー元として一度読み取り、countを一度評価する。コピー元は完了まで生存させ、先に余分な深いコピーを作らない。
2. countが非負であることを検査し、計算幅・配置サイズ・予算を検査して結果領域を確保する。
3. 要素を昇順に独立コピーする。入れ子の動的配列もコピーし、文字列の不変内容は保持する。
4. 結果の所有を渡し、一時的なコピー元を解放する。

0個でも両式を評価し、一時値を解放します。結果用の領域は確保せず、要素コピーもしません。valueの評価が失敗したらcountは実行せず、countの評価が失敗したらその診断を保ちます。途中の要素コピーで予算が尽きた場合も、repeat式の出自と先行出力を保持します。[表を作る例](../../examples/dynamic_arrays/repeat.ceru)と[0個の例](../../examples/dynamic_arrays/repeat_empty.ceru)で確認できます。

要素の代入では、各段の添字評価と境界検査を次の添字や右辺より先に行います。`a[bad][later()] = rhs()`の最初の検査が失敗したらlaterもrhsも実行しません。右辺の評価・コピーに失敗した場合、旧要素を先に解放しません。

| 診断 | 原因・出自 |
| --- | --- |
| `array-index-out-of-bounds`（既存） | 添字アクセス式 |
| `array-range-out-of-bounds` | 不正な範囲を指定した`array_copy_range`式 |
| `array-length-out-of-range` | 負のcountを渡した`array_repeat`式 |
| `allocation-size-overflow`（既存） | サイズの積・和、長さ、配置サイズを表現できない |
| `allocation-limit-exceeded`（既存） | 配列または文字列の明示予算を超える |
| `allocation-failed`（既存） | 予算内でもallocatorやmemory.growが失敗する |

コピーで追加した確保は、そのコピーを要求したソースの式を出自とします。生成helperのNodeIdは一意にし、元のSpanを維持します。すでに出力した内容を残し、無関係なアクセス違反やtrapを成功した診断扱いしません。

## 予算と寿命

配列用に`--array-heap-limit <bytes>`を追加しました。既定64 MiB、0と`i64::MAX`までの十進非負整数を認め、文字列用`--string-heap-limit`は意味を変えません。どちらも実行前・生成前の設定とし、IR・bytecodeに記録します。生成C・LLVM・QBE・WAT・ASM・自前Objectも同じ設定を使います。コンパイル時定数では初回は動的配列を許さず、固定長定数から実行時に明示コピーします。

経路ごとのポインタ幅・paddingで予算超過の位置が変わらないよう、**配列の生存要素領域を共通の計算単位で数える**規則です。物理メモリ上限ではありません。

| 要素型の計算幅 | バイト数 |
| --- | --- |
| bool・各整数・f32・f64 | 8 |
| string・動的配列の記述子 | 16 |
| 固定長配列 | 長さ×要素の計算幅 |
| 構造体 | 宣言順のフィールドの計算幅の和 |
| enum | タグ8＋全選択肢のフィールドの計算幅の和。非選択ペイロードの動的領域は生成しない |

配列の予算は`length × width(T)`を確保単位で計上し、入れ子の動的配列の要素領域を別に加算します。静的領域、局所記述子、管理ヘッダーを除き、文字列内容は従来の文字列予算で一度だけ数えます。空配列は0です。幅0の要素型も長さを保持し、0除算せずサイズ検査します。共通の計算幅と各ターゲットの実配置サイズの**両方**を検査し、wasm32へ変換する前に上位ビットを確認します。

再代入中は旧値と新値が同時に生存します。長さ3のi64配列の自己代入なら、配列予算は24から48バイトになり、旧値解放後に24へ戻ります。読み取りだけの`array_len(a)`や`print(a)`は24のままです。この差をテストして、最適化で隠れたコピーや失敗の移動を入れない基準にします。

ブロック・return・break・continueでは束縛を逆順、配列では要素を逆順に解放します。部分コピーには初期化済み要素数を持たせ、途中失敗で未初期化領域を読まないようにします。VMは失敗してホストへ戻る境界でも全残存領域を回収します。nativeは診断後にプロセス停止、WATは失敗したインスタンスを破棄する既存の境界を維持します。

## 生成過程で見えること

`array_copy`・`array_copy_range`・`array_repeat`と暗黙の値コピーを共通IRの通常のループ・分岐へ展開しました。`array.check-range`、`array.allocate-elements width=N`、`array.initialize-next`、`array.release-owner-last`、`array.free-elements`が実際の操作名です。

- 元の式の一度だけの評価と、読み取り・値コピー・一時値の所有移動の区別。
- 添字・範囲・長さ・サイズ・予算の検査。
- 要素領域の確保、昇順の要素コピー、初期化済み要素数の更新。
- 入れ子・フィールド・enumの選択中ペイロードへの型に沿った処理。
- 文字列の保持、旧値と一時値の解放、逆順の要素解放。

ASTの型、共通IR、backend IR、bytecode、成果物の対応を残します。配列全体を隠れたホスト関数で処理して終わらせず、要素走査は共通IRの通常のループ・分岐で追える形にします。各backendは配置・確保・load/store・解放の実装を担当し、値コピーの規則を個別に再定義しません。LLVM・ASM・objectでは既存の出自注釈も維持します。

IR ExecutorとVMは実行単位の型付き要素領域を管理し、同じ領域管理プリミティブを使います。命令の実行は独立し、要素コピーはそれぞれ共通IR／bytecodeのループで実行します。Cは下流のCコンパイラが選ぶターゲットの標準allocatorを使います。LLVM・QBE・ASM・自前COFF/ELFは明示ターゲットのallocatorとABIを使い、WATは非公開memoryを使います。領域の共有アドレスを利用者や観測APIへ公開しません。再帰的な型、外部値としての動的配列、借用・FFIはこの変更に含めません。

### 一時値からの所有の引き継ぎ

束縛からの値コピーは必ず独立した領域を確保します。一方、`make().field`のような所有する一時値からの抽出では、選んだ配列の所有を一時的に保持してから元の複合値を解放します。この短い引き継ぎだけに`array.retain-owner`と所有数を使い、copy-on-writeには使いません。最後の所有を外したときだけ共通IRの逆順ループで要素を解放し、`array.free-elements`で領域を回収します。無関係なフィールドの寿命を延ばさないため、次の引数に使える予算も保ちます。

IR ExecutorとVMの領域管理は、途中まで初期化した領域も実行境界で回収します。確保失敗・サイズ超過・予算超過は別々に検証し、所有管理の内部エラーを言語の停止として扱いません。

## Cへの対応

Cは所有領域へのポインタと長さの記述子を使います。管理領域は所有数・初期化済み要素数・論理予算を持ち、要素領域は型に合った`malloc`の配置を使います。空配列の確保は不要です。共通の計算幅と`sizeof(T)`による物理サイズを別々に検査し、予算超過と確保失敗を区別します。

要素コピー・比較・表示・逆順の解放は共通IRのループのままCへ出力します。C helperは領域管理と型付きload/storeだけを担当します。正常終了後の予算残存、確保失敗、部分コピーの予算超過をテストします。実行時停止では既存の診断後にプロセスを終了し、OSが残存領域を回収します。失敗から復帰するAPIは追加しません。

[同一ソース](../../tests/fixtures/dynamic-arrays/source.ceru)の[IR](../../tests/fixtures/dynamic-arrays/ir.ceir)・[bytecode](../../tests/fixtures/dynamic-arrays/bytecode.cebc)・[生成C](../../tests/fixtures/dynamic-arrays/c.c)を比較できます。[範囲を返す例](../../examples/dynamic_arrays/window.ceru)もIR・VM・C・LLVM・QBE・WAT・ASM・自前Objectで実行比較します。Cは`-O0`と`-O2`で比較し、LinuxではASan/UBSanも適用します。これは外部コンパイラの検証設定で、Ceruneに暗黙の最適化を追加するものではありません。

## LLVMへの対応

LLVMは`%cerune.array = { ptr, i64 }`で所有領域と長さを保持します。管理領域に要素領域のポインタ・所有数・論理予算・初期化済み数を持たせます。共通IRのコピー・表示・比較・逆順解放のループをそのままloweringし、確保と型付きload/storeをLLVMで実装します。

論理予算は共通IRの`width`、物理サイズは対象型の`getelementptr`から得るstrideで計算します。`bool`や`f32`の実配置が8バイト未満でも、予算は他経路と同じです。両方の積と符号付き64ビットの上限を確保前に検査します。長さ0は確保せず、幅0は長さを保ちます。

`--target x86_64-unknown-linux-gnu`または`--target x86_64-pc-windows-msvc`を必須とし、実行中のOSからは選びません。ターゲットの`malloc/free`と既存の出力・診断ABIを使います。生成後のコンパイル・リンクは外部Clangの責任です。

[LLVM fixture](../../tests/fixtures/dynamic-arrays/llvm.ll)と`--annotate-origins`で共通IRとの対応を確認できます。[構造体配列の例](../../examples/dynamic_arrays/readings.ceru)を含め、IR・VM・C・LLVM・QBE・WAT・ASM・自前Objectで出力を照合します。LLVMも`-O0`と`-O2`で、範囲・添字・予算・確保失敗の理由、NodeId／Span、先行出力を検査します。所有管理の内部trapだけでは成功扱いにしません。正常終了後は配列予算が0に戻ることも検査します。

## QBEへの対応

QBEは動的配列を管理領域へのポインタとして渡します。管理領域は要素ポインタ・長さ・所有数・論理予算・初期化済み数・strideを各8バイトで持ちます。空配列はnullです。内部の表現であり、利用者が共有可変ポインタを受け取るAPIは追加しません。

既存のQBE配置に合わせ、文字列と動的配列のポインタは物理的には8バイト、論理予算では16バイトです。全要素の物理strideと共通IRの計算幅を別々に検査・計上します。管理領域と要素領域は`malloc`で確保し、要素領域の確保に失敗した場合は管理領域を先に解放します。

コピー・比較・表示・逆順解放のループ、要素のstore／blit、初期化完了の記録が[生成SSA](../../tests/fixtures/dynamic-arrays/qbe.ssa)に残ります。検査には元の式のNodeId／Spanを渡し、所有管理だけの内部`hlt`を言語診断として扱いません。正常終了後の予算0、サイズ超過、二つの確保の失敗を検証します。

Linuxは`amd64_sysv`、Windowsは`amd64_win`を明示します。QBE 1.3で[分割して返す例](../../examples/dynamic_arrays/batches.ceru)を含めIR・VM・C・LLVM・QBE・WAT・ASM・自前Objectを比較し、[Windowsの引数規則](qbe-windows.ja.md)も配列と組み合わせて確認します。`array_repeat`も同じ共通IRと領域管理を使います。

## WATへの対応

WATは非公開のWasm32線形メモリを使い、動的配列を管理領域へのi32参照として関数へ渡します。空配列は0です。管理領域は次の配置です。

| offset（バイト） | 内容 |
| --- | --- |
| 0 / 4 | 次のブロックへのi32参照 / 解放済みフラグ |
| 8 / 16 / 24 | i64の所有数 / 初期化済み数 / 長さ |
| 32 / 40 / 48 | i64の論理バイト数 / 要素stride / 物理容量 |
| 56以降 | 要素領域 |

既存のWAT配置に合わせ、scalarの保存スロットは8バイトです。文字列・配列の参照はi32ですが、共通の論理予算では16バイトとして数えます。管理領域と要素領域をまとめて確保し、長さ・論理幅・Wasm32の物理サイズをi64で検査してからアドレスへ狭めます。添字もi64のまま検査します。

文字列と配列は物理領域の末尾位置を共有し、領域の重なりを防ぎます。生存予算と再利用リストは別々です。十分な容量の解放済みブロックを再利用し、なければ必要なページだけ`memory.grow`します。分割・結合・縮小は行わず、断片化や線形アドレス空間の不足で確保が失敗する場合があります。成功時は予算を返却し、trap後のインスタンスは破棄します。

所有数0と解放済みは区別します。共通IRの逆順要素解放が終わり、`array.free`を実行した時点で再利用を許可します。コピー・比較・表示・解放のループは共通IRのままloweringし、[生成WAT](../../tests/fixtures/dynamic-arrays/wat.wat)にも残します。検査のヘルパーは元のNodeId／SourceId／Spanを保持し、ホストには出力バイトだけを渡します。memoryや可変の診断状態をexportしません。

[文字列配列のexample](../../examples/dynamic_arrays/labels.ceru)を含む共通テストをIR・VM・C・LLVM・QBE・WAT・ASM・自前Objectで照合します。内部テストでは、サイズ超過・実際の`memory.grow`失敗・幅0・空配列・上位32ビットを持つ添字を区別し、同一インスタンスの成功実行を繰り返して配列と文字列の予算が0へ戻ることと、1ページ内での領域再利用も確認します。

## Windows/Linux ASMと自前Objectへの対応

Nativeは動的配列を管理領域への8バイト参照として渡します。管理領域と要素領域を一度の`malloc`で確保し、空配列はnullにします。共通IRのコピー・比較・表示・逆順解放のループをそのままloweringします。

| offset（バイト） | 内容 |
| --- | --- |
| 0 / 8 / 16 | 要素領域の基準ポインタ / 長さ / 所有数 |
| 24 / 32 / 40 | 論理バイト数 / 初期化済み数 / 要素stride |
| 48以降 | 要素領域 |

既存のNative ABIに合わせ、要素・構造体のフィールドは基準ポインタから8バイトずつ低いアドレスへ置きます。配列の内部参照は8バイトでも論理予算は16バイトです。論理サイズと、48バイトの管理領域を含む物理サイズを別々に検査してから確保します。予算は確保成功後に加算し、最終所有者が要素を解放した後の`array.free-elements`で返却します。参照を利用者に公開するAPIは追加しません。

Windows/Linuxのターゲットを明示し、各OSの引数配置と`malloc/free`・出力・停止の規則を使います。同じloweringからASMと自前COFF/ELFを生成し、どちらも外部リンカで実行ファイルにします。[Linux ASM](../../tests/fixtures/dynamic-arrays/linux.s)と[Windows ASM](../../tests/fixtures/dynamic-arrays/windows.s)、`--annotate-origins`で確保・要素のload/store・検査・解放を追えます。

[座標ペアのexample](../../examples/dynamic_arrays/coordinates.ceru)を含め、IR・VM・C・LLVM・QBE・WAT・ASM・自前Objectの出力と失敗記録を比較します。単体テストではサイズ超過、固定したmalloc失敗、空配列、幅0、所有数を検査し、繰り返し成功した実行の配列・文字列予算と管理リストが空になることを確認します。Windowsの診断文のCRLFだけはLFと揃えて比較し、文字列出力のNUL・CR・LFはそのまま比較します。所有管理の内部trapを言語上の検査失敗として成功扱いにしません。

## 現在実行できる基準例

`array_copy_lifetimes.ceru`は固定容量3の二重配列と使用数を組み合わせ、実際に確保した文字列をコピー・返却・更新します。関数内の局所値が消えた後の生存、入れ子のコピーの独立性、範囲の引数順、末尾の空範囲、不正な範囲、短絡を確認します。不正範囲は**例のenum値**で返し、提案中の停止診断を代用しているわけではありません。

```sh
cargo run --quiet -- run examples/array_copy_lifetimes.ceru --string-heap-limit 24
cargo run --quiet -- emit-ir examples/array_copy_lifetimes.ceru
cargo run --quiet -- emit-bytecode examples/array_copy_lifetimes.ceru
cargo run --quiet -- emit-llvm examples/array_copy_lifetimes.ceru --target x86_64-unknown-linux-gnu --annotate-origins
```

24バイトの文字列予算で成功します。選択元と選択結果は`["保存", "二"]`のまま、編集した配列だけが`["変更", "二"]`になります。使用数0でも`array_len(storage)`は3です。動的配列の空値・配列の確保失敗・可変長の格納はこの例では検証しません。現行IRでは値としての配列コピー、走査、文字列の保持・解放までを観察できます。
