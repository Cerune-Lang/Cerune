# 子プロセス結果の起動前予約

[English](subprocess-storage.en.md)

子を起動した後で結果領域の不足が分かると、外部への副作用を取り消せません。[共通runtime](subprocesses.ja.md)へ起動前の返却領域予約を追加し、内部の配列領域へ予約・確定・取消しを実装しました。**言語の`std:process::run`と共通IR命令はまだ未実装です。**

## 現在の実装

| 部品 | 実装したこと |
| --- | --- |
| `Processes::run_with_reservation` | 要求検査と転送buffer確保の後、時計取得・起動の前に予約関数を最大1回呼ぶ。結果と予約した所有物を返す |
| `ReservationError` | 容量・表現範囲不足は`OutputBudget`、実メモリ確保失敗は`AllocationFailed`。いずれも`Reserve`段階・未起動として返す |
| `ArrayHeap::reserve_byte_outputs` | stdout/stderrの上限分を既存配列heapに確保。2個目の失敗では1個目を解放 |
| `ReservedByteOutputs::finish` | 確認済みバイトを既存の即値へ変換し、有効長を確定。配列の再確保をしない |
| 予約所有物のDrop | 未公開の配列を取り消す。途中の初期化、戻り値の破棄、unwindにも対応 |

Rustの既存`Processes::run`は領域追加のない予約関数を使うため、既存の要求・結果・検査順は維持します。予約関数は実行APIの一部であり、読取り専用の観測APIではありません。領域確保だけを行い、OS操作・再試行・実行制御を追加しない契約です。

## 検査と所有の順序

1. 呼出し番号を確定し、接続停止・要求・要求容量・未接続を既存の順序で検査する。
2. 出力保持bufferと3個の転送bufferの容量を検査し、確保する。
3. 言語側などが必要とする返却領域を予約する。
4. 単調時計を取得し、期限を計算して、登録対象を一度だけ起動する。
5. 転送・終了・後始末を共通runtimeで処理し、結果と予約所有物を返す。
6. 呼出し元が予約領域へ結果を確定する。使わなければ取り消す。

段階3以前の失敗では時計取得・起動・後始末を行いません。予約失敗だけでは接続を無効化せず、次の明示呼出しを許します。段階3が成功したら、起動失敗や部分結果の場合にも同じ予約所有物を返します。`Option`が`Some`であることは起動成功を意味しません。

期限は予約後に時計を取得して計算します。既存どおり要求検査・領域確保の時間は子プロセスの実行期限に含めません。予約関数自身が停止しない場合やallocatorがabortした場合まで完了を保証するAPIではありません。

## 使用量と結果の確定

| 領域 | 使用量・寿命 |
| --- | --- |
| runtimeの生バイト | 両出力上限と3×4096バイトを`available_bytes`で制限。返却された生出力はRust Outcomeが所有 |
| 言語の配列 | 共通のu8格納幅8バイト×両出力上限を既存ArrayHeapへ加算。Rust内部の実要素サイズも別に検査・確保 |
| 確定後の短い結果 | 有効長は保持バイト数。予約capacity分の使用量は配列の解放まで減らさない。長さ0でも、非0上限で確保した領域は解放まで保持 |
| 変換中の両領域 | 生出力と確定先配列が同時に存在する。片方を消費したことにして使用量を隠さない |
| 失敗結果にも必要なReportの構造体・enum | `PreparedReport`で共通runtimeを呼ぶ前に全領域を確保。使用する既存値表現のVecとして保持し、ArrayHeapのバイト配列使用量には含めない |
| Outcomeの外側と要求変換 | **次の接続作業**。Reportと両配列を収める領域、要求文字列・配列からRustへの変換領域を起動前に準備する |

確定は両出力が予約長以内かを先に検査します。範囲外ならどちらも公開せず、両方を解放します。即値への変換関数は追加確保を行わない契約で、既存実行器の整数値構築へ使います。NUL・CR/LF・不正UTF-8をバイトのまま保持し、元の失敗・後始末結果・出自を変更しません。

予約中は配列heapを排他的に借用し、未初期化領域を利用者の配列として渡しません。確定後は既存のretain・release・freeと所有の展開へ戻します。観測履歴の設定や容量は、予約関数の呼出し数・結果・OS操作列を変えません。

## Reportの固定領域

[内部のReport変換](../../src/runtime/process/report_value.rs)を追加しました。現在は単体試験と共通runtimeの接続試験から使用し、言語命令からの呼出しは未実装です。

| 段階 | 処理 |
| --- | --- |
| 準備 | 呼出し元が渡す標準モジュールのReport型IDから、共通IRのフィールド名・順序・型・enum選択肢を検査する |
| 確保 | 入れ子と非選択側のenum領域も含めて`try_reserve_exact`で確保する。途中で失敗・破棄した場合は準備済み領域も解放する |
| 確定 | runtimeのReportを既存領域へ書き込む。確保・文字列化・OS操作は行わない。タグ番号は共通IRの選択肢名から取得する |

HIR/MIR/SSAの共通値とVM値の2表現に対応します。型IDやRust enumの番号を固定せず、既存の構造体・enum表現を使います。非選択側のpayloadは型に合うゼロ値で初期化します。

全21失敗分類、転送方向、終了コード・signal、確認済みバイト数、進行不明、後始末の判定と生報告、NodeId/SourceId/Spanを保持します。公開APIの時間単位はミリ秒なので、RustのDurationが整数ミリ秒のu64で表せない場合は変換エラーにし、丸めません。言語接続では要求の`timeout_ms`から正確に変換する必要があります。

形状不一致は内部の型接続エラー、確保失敗はCerune側の資源不足です。失敗値を作れない状態を子プロセスの失敗値や終了コードへ偽装しません。Reportの準備は要求検査で失敗した場合にも必要なため、`run_with_reservation`の呼出し前に行います。両出力配列の予約は従来どおり要求検査後の予約関数で行います。

## 検証と残りの接続

[配列予約テスト](../../src/runtime/array_heap/byte_outputs.rs)は0・上限ちょうど・短い結果、容量不足・実確保失敗・サイズ超過、2個目失敗時の取消し、変換途中のunwindを確認します。[共通runtimeの比較](../../src/runtime/process/tests/result_storage.rs)は未起動・既存検査の優先順・失敗後の継続・部分結果・予約所有物の一度だけの解放・観測の有無を確認します。

[Windows/Linuxの実OS検証](../../experiments/subprocess/README.md)にも予約失敗→次の明示実行を追加しました。非0終了と生バイトを保持し、確定前後の領域アドレス・capacityが同じことを確認します。これはRustの接続試験で、`.ceru`の実行機能ではありません。

```sh
cargo test --lib runtime::process
cargo test --lib runtime::array_heap
```

Report変換の試験は両値表現の全フィールド・全選択肢、タグ順序の変更、全確保箇所の失敗と解放、領域アドレスの保持、時間の正確性、仮想ソースの出自を確認します。共通runtimeとの試験では、要求検査失敗→予約失敗→次の明示呼出しと観測有無での一致を確認します。

次はOutcomeの外側と両配列を結び、1つの共通IR操作へ要求・返却値・出自を接続します。要求の文字列・配列からRustへの変換領域も起動前に確保します。失敗値自体を構築できない場合はCeruneの資源不足として扱い、子の終了コードへ偽装しません。各実行器の制御フローを共有したり、未対応の生成経路を成功で代用したりしません。
