# Floating-point rounding and route comparisons

[日本語](float-rounding.ja.md)

## Contract

Ordinary `f32` / `f64` arithmetic follows the expression tree and rounds each operation to binary32 / binary64 respectively. The default environment uses round-to-nearest, ties-to-even. `a * b + c` rounds after multiplication and again after addition. Contraction into FMA or reassociation that changes the result is disallowed. There is currently no explicit language FMA operation.

| Compared property | Contract |
| --- | --- |
| Finite values and infinities | Same values for identical inputs, types, and operation order; tolerances must not hide route differences |
| Signed zeros | Preserve the sign; compare bits or output that retains it |
| NaNs | Preserve NaN comparisons/classification; identical payload/sign bits across routes are not guaranteed |
| External FP environment | Host changes to rounding direction or subnormal handling are outside validated conditions. Observation must not change the environment or values |

Exact `convert` checks differ from ordinary arithmetic rounding; they do not recover an ideal real value from before rounding.

## Generated C conditions

Generated artifacts contain Clang's `#pragma clang fp contract(off)` and GCC's `#pragma GCC optimize ("fp-contract=off")`, testing Clang first. The control remains visible in generated code rather than existing only in test invocation flags.

Use external compiler settings that preserve NaNs, infinities, signed zeros, and per-operation rounding. `-ffast-math`, `-Ofast`, and Clang's pragma-overriding `-ffp-contract=fast` are outside validated conditions. Other C compilers and extended-precision targets require equivalent validation before being claimed supported.

See [Clang's FP controls](https://clang.llvm.org/docs/UsersManual.html#controlling-floating-point-behavior) and [GCC's floating-point implementation](https://gcc.gnu.org/onlinedocs/gcc/Floating-point-implementation.html). Clang's command-line and pragma controls interact; `-O0` alone does not prohibit contraction.

## Investigating #156 (2026-10-18)

[Issue #156](https://github.com/Cerune-Lang/Cerune/issues/156) records a generated-C/VM difference on Apple Silicon for linear regression. This investigation used Clang 22.1.8 on Windows x64 and GCC 9.4.0 on Linux x64. ARM64 assembly was cross-generated by Clang; execution on ARM64 hardware belongs to CI.

The minimal operations are these two functions:

```c
float step32(float a, float b, float c) { return a * b + c; }
double step64(double a, double b, double c) { return a * b + c; }
```

| Type | a / b / c (exactly representable) | Separately rounded bits | Fused bits |
| --- | --- | --- | --- |
| f32 | 1+2^-23 / 1-2^-23 / -1 | 00000000 | a8800000 (-2^-46) |
| f64 | 1+2^-52 / 1-2^-52 / -1 | 0000000000000000 | b970000000000000 (-2^-104) |

The exact product is slightly below 1 and rounds to 1 at each type's precision. Adding -1 then produces +0. FMA omits the intermediate rounding, retaining a tiny negative value.

| Condition | Observation |
| --- | --- |
| Clang x64, `-mfma`, O0/O2, no protection | Fused bits above; generated contraction control produces +0 for both types |
| Clang `--target=arm64-apple-darwin`, O0/O2 | Unprotected `fmadd` becomes `fmul` followed by `fadd` with contraction disabled |
| GCC x64, `-mfma -O2`, default language mode | Fused bits without protection; GCC pragma produces +0 for both types |
| GCC `-std=c11`, O0/O2 | Both +0 before the fix; testing only this mode misses the GCC difference |
| Generated linear regression, Clang x64 `-mfma -O0` | Changing contraction alone changes the first loss from 0.011821707721273521 to 0.011821707721273523, reproducing the report |

Contraction accounts for both the minimal example and the original program's observed difference. This does not assign the same cause to every future floating-point discrepancy.

## Validation and observation

- [Runnable example](../../examples/float_rounding.ceru): f32/f64 multiplication/addition, precision boundaries, negative zeros, infinity, and NaN. Prints `0, 0, 0, 0, -0, -0, true, true`, one per line.
- `tests/c_strings.rs`: passes volatile inputs to generated functions and reads return bits through memcpy, avoiding constant folding and formatting as explanations. Tests C11/default modes and O0/O2; explicitly enables FMA on x86 when supported.
- `tests/float_output.rs`: compares HIR, MIR, SSA, lowered SSA, and VM against known results; round-trips finite/negative-zero output to bits.
- `tests/dynamic_arrays.rs`: includes the example's array storage and compares C, LLVM, QBE, WAT, ASM, and self-encoded Object. Executed on Windows/Linux.
- C observation fixtures updated; baseline IR and existing operation origins remain visible.

```sh
cargo run -- run examples/float_rounding.ceru
cargo run -- emit-c examples/float_rounding.ceru -o target/float-rounding.c
cargo test --test c_strings floating_point_contraction -- --nocapture
cargo test --test float_output
cargo test --test dynamic_arrays floating_point -- --nocapture
```

Missing-tool skips are not successful execution comparisons. Set the existing `CERUNE_TEST_*` variables to require tools. This investigation does not add Darwin LLVM/QBE/Native support.
