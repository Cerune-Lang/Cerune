# 子プロセス実行の契約案

[English](subprocesses.en.md)

2026-11-02時点の設計案です。**子プロセスを言語から実行する機能は未実装です。** 関連Issueは[#89](https://github.com/Cerune-Lang/Cerune/issues/89)、[#173](https://github.com/Cerune-Lang/Cerune/issues/173)、副作用を重複させない比較は[#104](https://github.com/Cerune-Lang/Cerune/issues/104)で扱います。

## 方針と現在地

初版は、起動前に登録した実行対象をshellなしで呼び出し、上限付きで標準入力を送り、標準出力・標準エラー・終了状態を回収する同期操作を提案します。

ユーザーとの確認で、**子プロセスの失敗も観測でき、呼出し元が処理を継続できること**を優先する方針になりました。非0終了だけでなく、起動・転送・容量上限・時間上限の失敗も結果として返す方向です。既存のファイルI/Oが採る「操作失敗でCeruneを停止する」方式を、そのまま子プロセスへ適用しません。

| 区分 | 状態 |
| --- | --- |
| 既存の実装 | [限定ファイルI/O](file-io.ja.md)の読取り・新規保存、4実行器と既存生成経路の接続 |
| 既存の別用途 | `src/native_build/link.rs`のリンカ起動、`tests/support/process.rs`のテスト用実行 |
| 今回の設計案 | 登録した対象、明示argv、容量・時間上限、回復可能な操作結果、読取り専用の観測 |
| 実装前に確定すること | runのシグネチャ・結果領域の確保、上限の数値、登録設定の形式、各生成経路のABI |
| 初版に含めないこと | shell構文、対話端末、バックグラウンド実行、パイプライン構文、汎用ジョブ管理、未信頼コードのsandbox |

リンカ・テスト用の既存処理は、一時ファイルへの出力回収と時間上限を持ちます。しかし、言語側の出力容量契約、回復可能な結果型、完全な後始末の記録を満たす共通runtimeではありません。低水準処理を共有する場合も、ビルド・テストの用途とソースプログラムの実行意味を分けます。

## 共通runtimeの部分実装

`runtime::process::Processes<B>`へ[進行中転送の状態管理](subprocess-transfers.ja.md)を接続しました。[試験用接続](../../src/runtime/process/tests.rs)で要求・起動・転送・期限・終了監視・後始末を検証しています。[Windows実OS Backend](subprocess-windows.ja.md)を接続しました。[Linux Backend](subprocess-linux.ja.md)も接続済みです。[std:processの公開データ型](subprocess-values.ja.md)を追加しました。**`run`、子プロセス用IR命令、各実行器・生成経路への操作接続は未実装です。** 言語から子プロセスを起動できる状態ではありません。

| 部品 | 現在の扱い |
| --- | --- |
| `Request` / `Limits` | 対象名、引数、入力、両出力上限、`Duration`の期限を明示。上限の既定値は未設定 |
| `Processes::run` | 同期的に`Outcome`を返す。内部では3streamを並行して進め、回収を確認した通常の失敗後は次の明示呼出しを受け付ける |
| `Outcome` | stdout/stderr本文、出自・受理数・終了状態・失敗・後始末の`Report`、転送状態を保持。`completed()`は子の終了コード0を意味しない |
| `Backend::start` | 起動済み、未起動を確認、起動不明を区別。起動不明でも後始末を一度行う |
| `Backend::submit` | 最大4096バイトのbufferを所有権ごと受け取る。提出失敗も終端通知で返す |
| `Backend::poll` | 期限まで待ち、転送・取消し応答・子の終了・後始末を固定容量の`Batch`で返す |
| `Backend::cancel` | 進行中操作ごとに一度だけ要求。応答と転送終端は別々に返す |
| `Backend::begin_cleanup` | 起動済み/不明の操作で、成功時も失敗時も一度開始。後始末中もpollから遅れた通知を回収 |
| `events()` | 要求番号、段階、出自、各操作の要求/確認済み/保持数、状態、取消しと終端結果を読取り専用で保持。本文・対象名・引数は含まない |

Rustの接続契約を変更しました。旧`Poll`/`PollEvent`と借用buffer方式は本体から除き、[旧同期モデル](../../src/runtime/process/synchronous.rs)を比較テストだけに残しています。安定した埋込みABIではなく、既存の言語CLIや実OS接続への破壊的変更はありません。登録表・OS設定の所有は接続側に残し、試験用接続を利用者向けの実行経路へ公開しません。

検査の優先順は、接続停止、不正要求、要求容量、未接続、buffer使用量、確保、期限の加算可能性、起動です。要求容量には引数件数、対象名と引数の合計UTF-8バイト数、stdin長、stdout/stderr上限の合計、時間上限を含みます。空の対象名、NULを含む対象名/引数、0の実行時間/後始末時間は起動前に失敗します。呼出し番号の枯渇も、新規起動せず接続を停止します。

起動前に両出力の保持領域と3個の4096バイト転送bufferを予約します。`available_bytes`はその合計上限であり、言語の配列使用量ではありません。返却後の所有管理と`[u8]`への変換領域はIR接続時に追加します。短い結果でも予約capacityを縮小しません。

通知処理は時計の逆行・期限を先に検査し、stdin、stdout、stderr、取消し応答、終了状態、後始末報告の順です。期限に達していても受理数と部分本文は回収し、元の失敗を上書きしません。提示量を超える数、古い操作、重複終了、空の通常通知等は契約違反です。直接の子の終了だけで完了せず、正常経路にはstdin closeと両出力EOFも必要です。待機中断は再待機しますが、起動やcloseを暗黙に再試行しません。

後始末未完了、時計の逆行、後始末期限到達、進行不明、契約違反、未完了転送・取消し応答の欠落では接続を再利用しません。`cleanup_reported`に接続の報告、`cleanup`に期限等を判定した結果を残します。回収済み資源のフラグと終了要求の有無を失いません。停止した接続への次の要求は、時計取得・起動・転送・後始末を追加実行しません。

制御操作は待機せず、pollが期限付き待機を担当します。接続が契約を無視して戻らない場合、共通runtimeだけで強制中断はできません。待機、多重化の公平性、未回収資源の保持・終了時処理はOS接続で実測します。観測履歴の無効化・上限到達・確保失敗は結果や制御操作列を変えません。

検証コマンドです。

```text
cargo test --lib runtime::process
```

試験では同時通知の全6配列順、期限後の部分転送、取消し応答の遅着・欠落、EOF・上限、後始末、次の呼出し、観測の有無を比較します。正常終了・出力・時間切れ・容量超過は旧同期モデルとも結果を比較します。

[Windows/LinuxのOS試作](../../experiments/subprocess/README.md)では、argv・同時転送・期限・子孫回収など9ケースを検証済みです。Windowsは実行開始前のJob所属と活動数0、Linuxは専用監督プロセスでの子孫回収を確認しました。[実OS接続設計](subprocess-os.ja.md)を追加し、Linuxの専用監督が呼出し元の設定や別の子を妨げないことも実測しました。[制御通信・fd受渡しとWindowsの非同期I/O・取消し](../../experiments/subprocess/transport/README.md)を起動・管理範囲へ接続し、継承制限、切断・終了時の孫とI/O回収まで確認しました。Windowsは本体Backendと共通期限・終端・後始末報告を接続済みです。`CallContext`で起動にも呼出し番号・出自を渡します。[Linux Backend](subprocess-linux.ja.md)も接続済みです。公開データ型を追加しました。次は結果領域の確保と共通IRへの操作接続です。

## 呼出しと接続

仮想標準モジュール `std:process`のデータ型は実装済みで、操作は `run` を予定します。[既存の標準モジュール](standard-modules.ja.md)と同じ予約名・仮想ソース・SourceIdを使い、相対importや暗黙のファイル探索を変更しません。

要求は以下を[Request型](subprocess-values.ja.md)で表現します。runのシグネチャと実行時の受理範囲は接続時に確定します。

| 要求 | 案 |
| --- | --- |
| 実行対象 | 接続側に登録した名前。接続は絶対実行パス、作業ディレクトリ、環境変数、引数の解釈方式を持つ |
| 引数 | `[string]`。左から評価し、空引数・空白・引用符・日本語を保持。NULは起動前の要求エラー |
| 標準入力 | `[u8]`。空なら直ちにEOF。改行追加、文字コード変換、Unicode正規化なし |
| 出力上限 | stdout/stderr別の最大バイト数。0も許容し、出力があれば超過 |
| 時間上限 | 有限の実時間上限。単調時計を使用。公開値は整数ミリ秒。指定可能範囲は接続時に固定 |

接続には引数件数・引数合計バイト数・stdin容量・出力容量・時間の上限も設定し、要求がそれを超えれば起動前に失敗値を返します。数値と検査順は共通runtimeの実装時に固定します。同期操作は1回ずつ扱い、並列起動APIは今回追加しません。

公開型の入力と出力はバイト列です。不正UTF-8も子プログラムの出力として保存できます。文字列への明示変換は別の純粋な処理として検討し、勝手な置換文字への変換や出力の破棄はしません。実際の転送APIと文字列変換の公開範囲は、後続の確認事項です。

登録がない場合は未接続の失敗値を返します。PATH探索、呼出し元の現在ディレクトリ、親の環境変数全体を暗黙に使いません。登録時に必要な環境を明示し、環境変数名の大小文字等のOS差も検査します。実行対象の登録は許可・設定であり、実行ファイルの内容不変性や子プロセスのファイルアクセス制限を保証しません。`std:fs`の作業範囲を子プロセスのsandboxと見なさないでください。

Windowsの通常のargv復元規則を使う実行ファイルを先行対象とし、独自のコマンド行解釈は別接続とします。`.bat`/`.cmd`やshellへの暗黙フォールバックは拒否します。Linuxでもshellへのフォールバックはしません。スクリプトを使う場合は、インタープリタを明示的な実行対象として登録する案です。[Rustの説明](https://doc.rust-lang.org/std/process/index.html)にも、Windowsの引数復元とバッチファイルの特別扱いが記載されています。

## 結果と回復

汎用Result型を追加することは前提にしません。既存のenum・構造体・所有する配列で、次の結果を表す案です。

| 結果 | 保持する情報 | 呼出し元の扱い |
| --- | --- | --- |
| 完了 | 終了状態、stdout、stderr、stdin受理数、後始末結果 | 0以外の終了コードも返す。成功と判断する条件は呼出し元が決める |
| 操作失敗 | 原因・段階・出自、起動状態、部分stdout/stderr、stdin受理数、取得できた終了状態、後始末結果 | `match`で分岐し、記録・別処理・次の呼出しを選べる |
| Cerune自体の失敗 | 値の構築不能など、既存の実行時停止理由とソース位置 | 子プロセスの終了コードへ偽装しない |

「完了」はCerune側の転送・回収が完了した意味です。終了状態は、通常の終了コード、Linuxのsignalによる終了、未取得を区別します。Windowsの32ビット終了値は保持し、符号付きへの切詰めやPOSIX signalへの推測変換はしません。

操作失敗は次のように分類します。公開名は[FailureCode](subprocess-values.ja.md)と同梱ソースで定義しています。

| 原因 | 区別する内容 |
| --- | --- |
| 要求・接続 | 不正な上限/NUL、未登録、未接続、未対応の接続、前回の後始末未完了による接続停止 |
| 起動 | 対象なし、実行不可、OS資源不足、その他の起動失敗。起動の有無が不明なら不明と記録 |
| 転送 | stdin書込み・close、stdout/stderr読取り、0進行、接続契約違反 |
| 容量 | stdout上限、stderr上限、起動前の要求・結果領域の上限 |
| 時間 | 操作の期限切れ。後始末の期限切れとは区別 |
| 回収 | 待機・終了状態取得・終了要求・ハンドル回収の失敗 |

操作ごとに結果を確定し、通常の失敗後も同じ接続で再実行できます。既存ファイルruntimeの「最初の失敗後は全操作を停止する」状態をそのまま共有しません。再試行は呼出し元の明示した新しい呼出しだけです。前回の外部副作用を巻き戻したことにはしません。

後始末を確認できない場合も、元の失敗と後始末結果を返し、呼出し元は処理を継続できます。ただし同じプロセス接続からの新規起動は停止し、以後の要求は副作用なく接続停止を返す案です。runtimeが残る管理情報を保持し、実行終了時の後始末も有限の手順にします。未回収の子が残る可能性を隠して「終了済み」と報告しません。この状態遷移と資源の寿命は、OS試作で検証する必須項目です。

## 転送・上限・終了の規則

1. 引数式の評価後、要求・接続・容量を検査します。失敗すれば起動しません。出力領域と結果値の必要量を検査し、転送バイト上限とCeruneの配列領域上限を区別します。`[u8]`の物理表現を1要素1バイトと仮定しません。
2. 起動試行の直前から期限を測ります。stdin送信、stdout/stderr回収、終了監視を並行して進め、pipe満杯による相互待ちを避けます。入力を全送信してから出力を読む方式にはしません。
3. stdinを全送信したら書込み側を閉じます。受理数はOS接続が受理した数であり、子が読み取った数ではありません。子が先に入力を閉じた場合は、未送信数を保持した転送失敗です。中断された転送の再試行は進行数が確定した場合に限り、起動そのものは自動再試行しません。
4. stdout/stderr内のバイト順は保持します。二つのstream間の全順序は約束せず、Ceruneのstdoutへ自動転送せず、親のprint/flushも暗黙に実行しません。上限ちょうどではEOF確認が必要です。各streamの追加読取りは最大1バイトとし、超過検出用バイトは結果配列に含めず、読取り済み数と保持数の違いを記録します。
5. 正常な回収にはstdin送信・close、両出力のEOF、直接の子の終了状態が必要です。直接の子が終了しても子孫がpipeを保持していれば完了ではありません。期限は出力回収中も有効です。[pipeのEOF条件](https://man7.org/linux/man-pages/man7/pipe.7.html)を前提にします。
6. 完了を確定する前に観測した時計が期限以上なら時間切れにします。同時に届いた複数の事象の選択順は共通状態機械で固定し、試験用接続で検証します。OS呼出しの停止やスケジューリングの遅れがあるため、指定時間内に必ず呼出しから戻る保証ではありません。
7. 失敗したら通常の転送を止め、管理対象へ終了を要求し、直接の子を回収してハンドルを閉じます。後始末には別の有限上限を設けます。部分出力と受理数は保持し、原因を後始末失敗で上書きしません。

成功時にも管理対象の子孫を残さない終了処理を設計します。残る子孫への終了要求が必要だった事実を記録し、黙ってバックグラウンド実行へ変えません。

Linuxは専用process group、WindowsはJob Objectを候補とします。Linuxの子孫は[setsid](https://man7.org/linux/man-pages/man2/setsid.2.html)等でgroupを離れ得るため、全子孫の封じ込めとは言いません。Windowsはユーザーコード実行前にJobへの所属を確定させ、[Jobの継承・breakaway条件](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)を明示します。どちらも任意の未信頼コードに対するsandboxではありません。後始末記録には「直接の子を回収した」「管理範囲へ終了を要求した」「未確認」を分けます。

## 可観測性と各経路

共通IRに副作用を持つ明示操作を設け、HIR→MIR→SSA→bytecode/LIRと生成コードまで、要求・結果・NodeId/Span・SourceIdの対応を残します。標準モジュール内の操作位置と利用者の呼出し位置を両方追跡します。最適化で呼出しを削除・複製・移動せず、非最適化表現も従来どおり取得できます。

観測記録は要求番号、登録対象の識別子、各段階、指定上限、要求/受理/保持バイト数、終了状態、失敗、後始末、出自を持つ案です。引数、環境値、stdin/stdout/stderr本文、絶対パスを診断へ自動掲載しません。結果の本文はプログラムの値として利用できますが、観測APIから読取り位置、期限、起動、再試行、終了要求を操作できません。

操作結果は実行の必須状態、観測履歴は読取り専用の補助記録として分けます。履歴の無効化・上限到達・記録の確保失敗で、転送や結果値を変えません。実OSの期限付近の結果は負荷・計測コストの影響を受けるため、異なる実行で完全に同じ経過時間や停止理由になるとは保証しません。

| 経路 | 責務 |
| --- | --- |
| IR・MIR・SSA・VM | 共通の要求・結果・上限規則を共有。試験用接続と実OS接続を分離 |
| C・LLVM・QBE・Native | 同じ規則を明示runtime呼出しへlowering。targetと接続設定を明示 |
| WAT | 版付きhost契約で要求・結果を転送。内部memoryは非公開。必要なimportのないhostで成功扱いしない |
| build/release | 必要な接続契約・target・上限設定を記録。ローカルのパスや環境の秘密を配布物へ自動埋込みしない |
| compile/check/emit/観測 | ソースに書かれた子プロセスを起動しない。明示的なNativeリンクは別のビルド操作 |

既存の`--cerune-runtime-v1`のプログラム引数規則は維持します。登録ファイルやCLIオプション、host ABI、成果物形式の版は別途確定し、既存hostの変更範囲を実装前に列挙します。汎用的な副作用システムや記録・再生基盤は前提にしません。

段階導入中は未対応経路を明記し、成功する空実装で代用しません。全経路の比較が揃うまで、共通機能として完了とはしません。今は未実装APIの`.ceru`を実行example一覧へ追加しません。

試験には次のケースを含めます。

- 空引数、引用符、空白、日本語、NUL拒否。環境・cwdの明示と未接続時に起動しないこと。
- 0/非0終了、OS固有の異常終了、対象なし、実行不可。失敗を値として受けた後のprintと次の呼出し。
- 空入力/出力、NUL・CR/LF・不正UTF-8、stdinの早期close、短い転送・中断・0進行・契約違反。
- stdout/stderr同時大量出力、上限0/ちょうど/1バイト超過、結果領域不足、出力の片側だけの失敗。
- 時間切れ、期限と終了の競合、直接の子の終了後に残るpipe、子孫、終了要求・回収失敗と接続停止。
- 観測の有無/履歴上限による意味の不変性。失敗結果の部分配列をコピーした後の独立性。
- 各経路で同じ試験用応答を使う比較と、隔離した作業場所のOS試験。外部へ副作用を持つ同じ実プログラムを無断で経路数だけ繰り返さない。

OS試験の補助プログラムはshellに依存せず、argv・出力量・終了・待機を制御できる独立したfixtureにします。Parallax等の独立した期待値計算も保持します。既存ファイルI/Oの生成経路における成功操作の共通観測APIは[別の残件](file-io.ja.md)であり、子プロセス実装の完了と混同しません。
