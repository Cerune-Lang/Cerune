# WAT出力host契約 v1

[English](wat-output-host.en.md)

生成WATは通常出力のバイト数・再試行・停止を自身で管理します。hostへ渡すのはバイト値と応答だけです。内部memoryはimport/exportせず、公開する実行関数は従来どおり `main` だけです。

## 書込みとflush

必要な機能を使う生成物だけが、次の関数を `cerune` からimportします。

| import | 用途 |
| --- | --- |
| `write_stdout_v1(bits: i64, count: i32) -> i32` | 通常出力。下位バイトから順に `count` 個（1〜8）を渡す |
| `flush_stdout_v1() -> i32` | 明示flush。既存契約のまま、0が成功・それ以外が失敗 |
| `write_error_byte(byte: i32)` | 停止診断。既存のASCIIバイト配送 |

書込み応答は次のように区別します。

| 応答 | 意味と生成WATの処理 |
| --- | --- |
| 1〜count | その長さのprefixを受理。残りだけ再送 |
| 0 | 進行なしとして停止 |
| -1 | 書込み失敗として停止 |
| -2 | 今回は未受理の割込み（EINTR相当）。同じ残りを再試行 |
| count超過・その他の負値 | 契約外の受理数として停止 |

1回のhost呼出しを8バイト以内にすることで、可変memoryや内部addressを渡さずに短い書込みも表せます。OS呼出しの分割を他経路と揃える必要はありません。hostは符号付きi64のビットをそのまま解釈し、count以降のビットを無視します。文字コード・改行変換を挟みません。

要求/受理数は**共通IRの1出力操作全体**で数えます。数値・真偽値・文字列・複合値表示が対象です。配列などの表示は既存IRと同じ複数操作になります。失敗時は次の診断を出してtrapし、後続処理・再送・追加flushをしません。UTF-8の途中まで受理したprefixも取り消しません。

```text
cerune: io-v1 operation=write requested=N accepted=M node=N[ file=F] bytes=S..E
```

角括弧は複数ファイル時の任意項目を表し、実際には出力しません。応答の分類は生成コード内で区別し、既存 `io-v1` の形式へOS固有の番号は追加しません。受理は画面表示・永続保存の保証ではありません。

## 数値整形と正確なバイト数

整数と真偽値はWAT内で整形します。文字列は保持済みデータを読み、引用表示はエスケープ後の長さを先に数えます。出力全体のheap複製はしません。

浮動小数点を表示する生成物だけが、対応する整形importを要求します。

| import | 規則 |
| --- | --- |
| `format_f32_v1(value: f32, offset: i32) -> (i64, i32)` | 有効数字9桁 |
| `format_f64_v1(value: f64, offset: i32) -> (i64, i32)` | 有効数字17桁 |

返り値は `(bits, length)` です。lengthは**改行なしの整形結果全長**（1〜128バイト）、bitsはoffsetから最大8バイトを下位から詰めた値です。offsetは0、8、16…と進み、length未満の位置だけを要求します。末尾の不要ビットは読みません。

整形関数は同じ値へ同じ結果を返し、出力・flush・実行器への再入を行いません。[既存の数値表示規則](../reference/language.ja.md#出力)に従い、ロケール依存の小数点・桁区切りを入れません。WATは全chunkを非公開の固定128バイト領域へ受け、各応答の全長の一致と印字可能ASCIIを検査してから書込みを始めます。要求数は確定した全長と末尾LF、受理数は書込み接続の応答から得ます。

負の長さ・0・128超過・途中で変わる全長・不正な本文は、出自付きの `cerune: output formatting failed` 診断で停止します。まだ整形できていない本文の要求/受理数は捏造しません。WATがhostの整形計算全体の正しさを証明するわけではなく、数値表示規則の実装はhostの責務です。

## 移行と互換性

新生成物の通常出力は、旧 `print_*`・`write_i64/u64/f32/f64`・`write_byte` importを使いません。既存hostには次の更新が必要です。

| host・生成物 | 動作 |
| --- | --- |
| 新生成物＋旧host | 必須import欠落でinstantiateに失敗。旧関数へのfallbackはしない |
| 新生成物＋更新host | 新しい応答契約で実行 |
| 旧生成物 | 旧ABIのまま。更新hostで動かすなら旧importを別途維持 |
| flushのみ／出力なし | 通常書込み・整形importは不要 |
| float表示なし | float整形importは不要 |

リポジトリ内は `tests/support/run_wasm.cjs` が共通hostです。文字列・動的配列・複数ファイル・実行時診断・flushのテストがこれを利用します。旧importは旧診断fixture用に残しますが、新生成物の失敗を成功へ置き換える互換処理はありません。外部hostの利用者は新importを追加してから新生成物へ移行してください。

hostはOSエラーを上の応答へ変換します。host自身の例外は通常の書込み失敗契約の外であり、受理数を推測して診断しません。診断配送もbest effortです。同一instanceへの同期再入・並行実行は対象外とし、停止したinstanceは再利用しません。

## 観測と検証

WAT側の `Output { kind, newline, origin }` から、生成された `cerune_output_*` の計数・整形・再試行・停止を追えます。実行用hostを選ぶことと、実行記録を読むことは別です。観測から接続応答を変更するAPIは追加しません。成功操作を含む生成経路共通の記録APIは後続です。

[比較テスト](../../tests/wat_output.rs)は、4実行器と同じ制御応答で、短い書込み・割込み・0進行・不正応答・部分失敗・出自・観測容量の独立性を確認します。旧hostの拒否、不要importの非要求、整形失敗、UTF-8途中・NUL・CR/LF・長い文字列、floatの極値も検証します。[output_values.ceru](../../examples/io_protocol/output_values.ceru)はそのまま実行し、既存の期待値と比較します。テストhostのfloat整形は整数比から偶数丸めし、有限の正確値だけに限定しません。
