# 明示的な整数読取り

[English](integer-parsing.en.md)

## 公開契約

`import "std:num" as num;` で予約済み仮想標準モジュールを読み込み、`num::parse_i64(text)` を呼びます。結果は既存のenum `num::ParseI64` です。

| 結果 | 意味 |
| --- | --- |
| `Value { value: i64 }` | 読取り成功 |
| `InvalidFormat {}` | 全文がASCIIの `-?[0-9]+` に一致しない |
| `OutOfRange {}` | 書式は正しいがi64の範囲外 |

- 先頭の0を許し、`-0` は0です。最小値は `-9223372036854775808`、最大値は `9223372036854775807` です。
- 空文字、符号だけ、`+`、空白、CR/LF、NUL、全角数字、小数、指数、区切り文字、基数接頭辞を受理しません。前後の文字を削除せず、Unicodeの正規化もしません。
- 全文の書式検査が範囲判定より先です。巨大な数字列でも末尾が `x` なら `InvalidFormat` です。
- 入力文字列を変更せず、I/O、追加の文字列確保、再試行を行いません。不正な入力は値として返し、既存の資源上限による停止は読取り結果に変換しません。
- u64・他の整数型・浮動小数点の読取り、暗黙変換、定数式での関数評価、汎用Result型は今回の対象外です。

## 実装と観測

書式と範囲の判定は同梱の [`src/standard/num.ceru`](../../src/standard/num.ceru) に一度だけ実装します。標準モジュールの本文を通常のfrontendで処理するため、ループ・比較・演算・enum構築がHIR以降に残ります。負の値として桁を蓄積し、各乗算・減算の前に範囲を検査して、最小値でも中間値を桁あふれさせません。

`std:num` は契約版1の仮想ソースです。同じコンパイル内の別名importは同じ型とSourceIdを参照します。本文と出自は既存のソース観測APIで取得でき、利用者ソースと区別できます。相対import規則を変更せず、`compile(&str)` 等からの利用でもファイル・環境変数を探索しません。SourceIdはコンパイル内の識別子であり、永続的な固定番号ではありません。

共通IRへ追加するのは内部用の純粋操作 `StringByteAt(value, index)` だけです。

| 項目 | 契約 |
| --- | --- |
| 引数 | stringとi64。文字列、添字の順に各1回評価 |
| 正常値 | UTF-8表現の1バイトをi64の0..255で返す |
| 範囲外 | 負の添字、長さ以上の添字は-1。メモリを参照しない |
| 文字列 | NULを含む生バイト。復号・正規化・変更・確保なし |
| 出自 | 呼出しのNodeId/SpanをHIR・MIR・SSA・Bytecode・LIRと生成処理へ保持 |

`__cerune_string_byte_at` は `std:num` の本文だけでIR操作へ解決します。利用者ソースから呼ぶ公開APIではありません。各実行器と生成経路はバイト参照だけを実装し、数値の書式や範囲を独自に解釈しません。libcの整数パーサも呼びません。WATのmemory公開やhost契約追加は不要です。観測操作はこれらの入力・状態を変更しません。

## 検証とexample

独立したASCII書式検査とRustのi64読取りを期待値に使い、HIR・MIR・SSA・VM・C・LLVM・QBE・WAT・Native ASM/Objectを比較します。範囲端、長い先頭0、不正書式、UTF-8のバイト参照、負・巨大な添字、短絡、引数の単一評価、配列コピー、少ない文字列上限での繰返しを検証します。NativeはMIR/SSAの両方を検証します。既存のツール必須CIで外部処理系も実行します。

- [基本例](../../examples/integer_parsing/README.md)：成功・書式不正・範囲外。
- [引数のseed例](../../examples/arguments/README.md)：整数読取りと、用途に応じたseed・回数の検査。

seed例の0..2147483646と回数0..100は、そのexampleの用途上の制約です。`parse_i64` の受理範囲ではありません。診断文へ引数の本文を自動で含めません。
