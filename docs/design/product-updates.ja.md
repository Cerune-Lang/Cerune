# 構造体の更新式

日本語 | [English](product-updates.en.md)

**状態: 実装済み**

## 用途と構文

既存の構造体から一部のフィールドを変更した、新しい値を作ります。

```cerune
type Point { x: i64, y: i64, }
before: Point = Point { x: 1, y: 2 };
after: Point = Point { ..before, x: 3 };
print(before.x); // 1
print(after.x);  // 3
print(after.y);  // 2
```

`Type { ..base, field: expression, ... }`と書きます。変更がなければ`Type { ..base }`、末尾のカンマも使えます。モジュールの型名も指定できます。フィールドへの直接代入や、新しい型を作る構文ではありません。

## 評価の契約

1. `base`を一度だけ評価し、値をコピーします。指定した型と同じ名前付き型が必要です。
2. 明示したフィールドの式を、ソースの記述順に一度ずつ評価します。
3. 指定しなかったフィールドはコピーから引き継ぎます。型定義の既定値は再評価しません。
4. 新しい値を返します。`mut`な変数への再代入や、配列要素への代入にも使えます。

すべてのフィールドを置き換えても`base`を省略せず評価します。新しい値の配列や入れ子を後で更新しても、元の値へ変更は伝わりません。文字列は不変なバイト列として引き継ぎます。

途中で失敗すると、後続の式と代入を実行しません。すでに行った`print`は残り、失敗した式のソース位置を報告します。短絡評価で式自体を省略した場合は`base`も評価しません。配列への代入では従来どおり、左辺の添字検査が右辺の更新式より先です。

元の値は先頭に一つだけ指定できます。後置・重複した`..base`、未知・重複したフィールド、型不一致はコンパイルエラーです。フィールド集合が同じ別の型も受け付けません。`Type {}`とフィールドの直接代入は未対応です。元の値を求める式の中でも再帰呼出しを使えます。

## この表記を選んだ理由

既存の構築式へ`..base`を追加することで、型と変更箇所を同じ場所に書けます。以前の候補だった`with`用の予約語は追加しません。

元の値を先頭に限定すると、左から右へ読む順番と評価順が一致します。末尾に書いた元の値を先に評価する規則や、複数の元の値を合成する優先順位は導入しません。省略フィールドの既定値を再実行すると元の値と異なる結果や副作用が生じるため、すでに保存された値を引き継ぎます。

## 各表現への変換

| 経路 | 処理 |
| --- | --- |
| Cerune IR | `Construct`に元の式と明示フィールドを保持。テキストは`base = ... [copy]`を表示し、各式のNodeId・Spanを保持 |
| bytecode / VM | 元の値、変更値の順に評価し、`construct.from_base`で新しい値を作成 |
| C | 型付き一時変数へコピーし、カンマ式でフィールドの評価と代入順を固定 |
| LLVM | 元の集約値へ`insertvalue`を適用して新しい集約値を作成 |
| QBE / WAT / x86-64 | 別の一時領域へコピーしてから、指定フィールドを更新 |
| 自前オブジェクト | ASMと共通のloweringを使い、ELF / COFFへ符号化 |

物理的なコピー回数や配置は言語仕様ではありません。上の実装でも、コピー後の値の独立性・評価順・診断は共通です。既存の構築式には変更を加えず、元の値がなければ明示値の後に省略フィールドの既定値を評価します。

## exampleと検証

- [product_update](../../examples/product_update.ceru)：u64、文字列、配列、入れ子の構造体を更新し、元の値と比較。
- [product_update_order](../../examples/product_update_order.ceru)：元の値・明示値の順序、既定値、短絡評価、繰り返しを表示。
- [modules/product_update](../../examples/modules/product_update.ceru)：公開型と関数をimportして更新。
- [modules/product_update_failure](../../examples/modules/product_update_failure.ceru)：元の値の評価中に失敗し、後続を実行せず、import先の位置と先行出力を保持。
- [packet_counter](../../examples/packet_counter.ceru)：既存の処理を更新式へ置き換え、出力を維持。

型と構文のエラー、元の値を介した再帰、IRとbytecodeの出自を検証します。正常例と失敗例をVM・C・LLVM・QBE・WAT・Windows/Linux ASM・自前オブジェクトで比較し、停止理由・位置・停止前の出力も照合します。
