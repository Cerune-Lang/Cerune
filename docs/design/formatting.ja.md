# optional letとソース整形

[English](formatting.en.md)

## 範囲と契約

`let`は束縛を見つけやすくする任意の表記です。通常の束縛、for初期化、配列反復の各束縛で `let mut? name: type = ...` 等を受理します。`:`は必須です。初期値を持つ束縛は[後続のinfer省略](infer-omission.ja.md)にも対応します。配列反復は型指定（`infer`を含む）が必要です。else if・条件式は未実装です。

`let`は予約語にせず、束縛位置で次が識別子または`mut`の場合だけ接頭辞と解釈します。既存の `let: i64 = 1;`、`let(...)`、`let = ...` 等は維持します。`let let: i64 = 1;`も可能です。更新節・定数・関数引数・フィールドへ接頭辞を広げません。

Parserは従来と同じ束縛ASTを構築し、`parse_module_with_syntax`で接頭辞の有無と元ソース上のSpanを別に返します。意味解析・IR・各実行器にlet有無の分岐は追加しません。

## fmtの初版

`cerune fmt <file> [--let preserve|show|hide] [--check | --write | -o <file>]` で単一ファイルを整形します。

| 選択 | 動作 |
| --- | --- |
| 既定 | 整形結果をstdoutへ出力。入力ファイルは変更しない |
| `--let preserve` | 元のletの有無を保持（既定） |
| `--let show` / `hide` | すべての束縛接頭辞を追加／除去。識別子のletには作用しない |
| `--check` | 未整形なら終了1。ファイル・stdoutは変更しない |
| `--write` | 明示した入力だけを置換 |
| `-o` | 指定した出力先へ保存。check・writeとの併用不可 |

初版は4空白のインデント、区切り・演算子の空白、ブロックの改行、末尾改行を揃えます。値の構築・matchパターン・enumのpayloadはコンパクトに保ち、型引数の山括弧と比較演算子を区別します。空の入力は空のままです。任意の折返し幅、設定ファイル、importの整列・再帰的整形は提供しません。空行は最大1行を保持します。

コメントと文字列・数値リテラルの表記は元ソースからコピーします。文字列内部の日本語・エスケープ・NUL・CR/LFは書き換えません。コードの改行はLFに揃えます。行コメント本文は保持し、末尾のCRは行末形式として扱います。

整形は構文だけを確認し、import先を読まず、型を推論したりコードを実行したりしません。未取得の依存を持つファイルも整形できます。構文エラー・不正UTF-8・上限超過・オプションエラーでは書込みません。ファイル入力の上限は既存loaderの既定単一ファイル上限（8 MiB）と同じです。保存時は同一ディレクトリの一時ファイルを用い、シンボリックリンクの置換は拒否します。

## 意味と出自の検証

出力を再度字句・構文解析し、実際の束縛接頭辞だけを除いたtoken列が一致することを確認してから返します。コメントも字句間の元テキストから保持します。新しい解釈規則やASTからのソース再生成で元の表記を失う処理は追加しません。

元ソースのSpanを整形後に流用しません。それぞれをコンパイルすれば、それぞれの正しいSourceId/Spanと生成過程を観測できます。位置情報・出自付き生成物がバイト単位で一致するとは主張せず、意味・型・評価順・短絡・コピー・停止理由が一致することを検証します。fmt自体は明示的な変換操作で、emit-sources等の観測APIは読み取り専用のままです。

既存exampleを3方針で整形し、再整形の冪等性、コメント・tokenの保持、IRの意味、全実行・生成経路、元／整形後の失敗位置を比較します。CLIは書込みの明示性、check、エラー時の既存ファイル保持も検証します。
