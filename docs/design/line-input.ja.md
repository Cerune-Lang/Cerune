# 上限付きUTF-8行入力

[English](line-input.en.md)

[標準入出力](standard-io.ja.md)の行入力契約です。初版は行／EOFを返し、異常時は出自付き診断で停止します。将来の回復可能な別APIのために、読取り結果と停止方針を分離します。

## 実装の範囲

[仮想標準モジュールstd:io](standard-modules.ja.md)と共通IRの入力命令を実装しました。HIR・MIR・SSA・VMはRustのrun_with_io APIで入力接続を受けます。[CLIと生成C・LLVMの実stdin接続](stdin-connections.ja.md)も実装済みです。**QBE・WAT・Nativeの入力は未実装です。** 未設定入力はEOFではなく診断で停止します。

既存enumの値付き選択肢で「行（string）／EOF」を表現できます。空行はLFまたはCRLFを含む行です。汎用Result型は前提にしません。公開APIは `import "std:io" as io;` と `io::read_line(max_bytes)`、結果型は `io::ReadLine` です。以下のRust接続APIは実行用の部品です。

## バイトと終了の契約

入力は厳密なUTF-8です。日本語、NUL、単独CR、結合文字を保持し、Unicode正規化・置換・改行削除をしません。LFで行を区切り、CR単独では区切りません。バイト上限にはLFとその前のCRを含めます。

| 入力 / 上限 | 結果 | 今回の消費バイト数 |
| --- | --- | --- |
| 空ストリーム / 3 | EOF | 0 |
| LF / 1 | LFを含む空行 | 1 |
| CRLF / 2 | CRLFを含む空行 | 2 |
| abc EOF / 3 | 改行なしの最終行を一度返し、次はEOF | 3 |
| abc LF / 4 | 改行を含む行 | 4 |
| abc LF / 3 | 上限超過 | 4 |
| abcd残り / 3 | 上限超過。残りは読み捨てない | 4 |
| CR EOF / 1 | CRを含む最終行 | 1 |

初版は1バイトずつ要求します。上限ちょうどでLFがなければ、EOFか超過かを確認するためにもう1バイト要求します。最大消費は上限+1です。その1バイトを巻き戻したと扱わず、超過時の消費数に含めます。上限ちょうどのLFで終われば追加要求しません。

EOFを確認した接続はEOFを保持し、後続の呼出しでOSやreaderへ再アクセスしません。改行なしの最終行を返した場合も同じです。新しいストリームとして読み直す操作やEOF解除は、初版に含めません。

## 検査・予算・失敗の順序

実行ごとに接続を作ります。既に失敗した接続は最初の失敗を返し、引数の再検査・再読取り・追加記録をしません。新しい操作は次の順で行います。

1. 上限を一度だけ評価する。共通範囲は1〜2147483647バイトとし、0・負数・範囲外を拒否する。
2. 入力接続の有無を検査する。未設定はEOFではない。
3. EOFを既に確認済みなら、読取りも領域予約もせずEOFを返す。
4. 上限分を、生存する動的文字列と同じ論理予算から予約する。予算不足や物理確保失敗は読取り前に止める。
5. LF・EOF・超過・読取り失敗まで読む。割込みは消費0の応答として同じ読取りを再試行する。それ以外の失敗は再試行しない。
6. 行が完成してから厳密UTF-8検証を行う。成功時は不変文字列へ所有を渡し、論理使用量を実際の行長に縮める。失敗・空EOF時は作業領域を解放する。

UTF-8検査より行の完成条件を先に判定します。不正バイトを含む長すぎる行は上限超過、未完成行の途中の読取り失敗は読取り失敗です。最後のバイトを読んだ後のEOF確認が失敗した場合も、部分行を成功として返しません。

一時領域と完成文字列を丸ごと二重確保せず、所有を移します。論理予算はバイト数であり、物理capacity・allocatorの管理領域とは区別します。完成文字列には上限分のcapacityが残るため、この予算は物理メモリ使用量の上限を保証しません。上限を大きく指定すると、実際の行が短くても事前予約で拒否されます。未確認のEOFにも予約は必要ですが、確認済みEOFには不要です。

Rust部品のread_lineは、呼出し側が与えるavailable_bytesを今回の予算として検査します。4実行器はStringHeapの残量を使い、読取り前に上限分の予算と所有情報を予約します。成功時は元の本文領域を移して実長を課金し、EOF・失敗では予約を解放します。予約中のheapは排他的に借用し、別の文字列割当てを挟みません。コピーの保持と最後の解放も既存の所有処理を使います。

失敗は次のコードで区別します。予算不足をOS読取り失敗として報告しません。

| コード | 条件 |
| --- | --- |
| invalid-limit | 上限が共通範囲外 |
| unconfigured | 入力接続なし |
| unsupported-connection | Windows console等、初版で扱わない実接続 |
| budget-exceeded | 予約できる論理予算が不足 |
| allocation-failed | 物理的な作業領域を確保できない |
| read-failed | 割込み以外のreaderエラー |
| invalid-response | 1バイト要求に1を超える受理数など、接続契約に反する応答 |
| invalid-utf8 | 完成した行が厳密UTF-8でない |
| limit-exceeded | 上限+1バイトを消費して超過を確認 |

## 接続・停止・回復の責務

内部の読取り処理は行／EOF／分類済み失敗と消費数を返します。Inputは最初の失敗を保持する停止方針を適用し、失敗後に接続を使いません。将来の別APIでは内部結果を再利用できますが、再開位置・残りを捨てる明示操作・予算を定義する必要があります。現在のInputを観測側からresetするAPIは作りません。

readerの契約は、1バイト要求に0（EOF）または1を返し、エラーや割込みではバイトを消費しないことです。要求より先を隠れて消費してはなりません。契約外の数を返したときは、直前までに確認した消費数を保持し、その応答での実消費は不明と記録します。偽の正確な数や巻戻しを報告しません。

実stdinはWindows/Linuxの同期pipe/fileを先行して実装しました。Windows consoleは専用診断で停止し、文字変換は後続です。生成targetを実行中のOSから推測しません。WATは版付きの値／状態importを別途定義し、内部memoryを公開しません。読取り自体は出力をflushしません。

## 診断と観測

失敗記録はASCIIで、入力本文・OSエラー本文・パスを含みません。既存の書込み／flush診断を変更せず、入力操作の欄を追加します。

~~~text
io-v1 operation=read-line code=limit-exceeded limit=3 consumed=4 consumption=known node=7 file=2 bytes=10..22
~~~

fileは匿名ソースでは省略します。bytesはソースのSpanであり、入力本文の範囲ではありません。consumedは当該操作で確認できた消費数です。契約外応答ではconsumption=unknownとし、それ以外はknownです。連続する呼出しでは順序番号と個々の消費数から対応を追えます。

観測記録は順序番号、NodeId/Span、上限、確認済み消費数、消費数の完全性、行／EOF／失敗、読取り要求数、割込み数を持ちます。read_callsはEOF確認・割込みの要求も含み、生成経路間でOS呼出し回数の一致は要求しません。公開する観測APIは不変参照だけです。記録上限や記録用確保失敗はtruncatedで示し、実行結果を変えません。本文を記録せず、観測callbackで読取りを行いません。

## 異常系と経路比較の完了条件

[共通接続テスト](../../tests/line_input.rs)は、次の入力・状態を先に固定します。物理確保失敗は本体の単体テストで注入し、巨大割当てやOSの偶然に依存しません。

| 対象 | 必須の期待値 |
| --- | --- |
| LF、CRLF、CR、NUL、日本語、結合文字 | バイト保持、空行とEOFの区別、非正規化 |
| 上限の前後、最終行、EOF | 正確な消費数、追加確認1バイト、EOF後の非読取り |
| 不正UTF-8、途中エラー、割込み | エラー優先順、部分行を返さない、割込み以外の再試行なし |
| 0・負数・範囲外・予算不足・確保失敗 | 読取り0回、別コード、出自の保持 |
| 契約外の数、失敗後の再呼出し | 不明な消費を明示、元の失敗を保持、追加作用なし |
| 観測なし・十分な容量・容量超過 | 結果・消費・接続への要求が一致 |
| 複数ファイルと機密本文 | 正しいNodeId/Span、本文を診断へ漏らさない |

経路への接続後は、各経路に独立した同一入力・応答を渡して比較します。一つの消費済みストリームを使い回しません。

| 経路 | 比較内容 | 現在 |
| --- | --- | --- |
| HIR・MIR・SSA・VM | 行／EOF、先行出力、停止理由と出自、消費数、所有と解放 | Rust APIで実装・比較済み |
| C / LLVM | 同じ入力、先行出力と停止診断、所有、実file/pipe・-O0/-O2比較 | 実装済み |
| QBE・WAT | 同じ入力、要求／応答、先行出力と停止診断、後続処理なし | 未実装 |
| LIR・ASM・自前Object（通常／SSA） | 入力操作の出自、明示target、同じ失敗と先行出力 | 未実装 |
| CLI／実OS | 質問をprint→flushしてから入力。flush失敗なら読取り0回 | Windows/Linuxのpipe/fileで実装。Windows consoleは未対応 |

全経路が揃った後で実stdinの対話exampleを追加します。既存の固定データによるinput_flowを実stdin対応と表示しません。観測での記録取得と、実行接続による入力供給を分離したまま検証します。
