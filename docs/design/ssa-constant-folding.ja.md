# 最初の最適化pass：SSAの定数畳み込み

[English](ssa-constant-folding.en.md) · [SSA](mir-ssa.ja.md) · [Issue #94](https://github.com/Cerune-Lang/Cerune/issues/94)

## 状態と選択

**設計段階です。最適化pass・pass指定CLI・最適化付きbundleは未実装です。** この変更では確認用のCerune例を追加し、既存経路で最適化前の意味を確かめます。SSA化とSSA→MIRは引き続き表現変換であり、最適化を暗黙に行いません。

最初は、同じブロック内で定数と確定した整数・真偽値の演算を、同じ位置のliteralへ置き換える `ssa-const-fold-v1` を実装する方針です。式の形から値を推測せず、型付きの既知値と既存の演算規則を使います。

候補を次の観点で比較しました。

| 候補 | 必要な保存条件 | 順序 |
| --- | --- | --- |
| 定数畳み込み | 型ごとの値域、演算の成否、元の命令位置と停止出自 | 最初。命令数・CFG・IDを維持できる |
| copy伝播・除去 | 支配、loopでの再実行、並列受渡し、除去命令の対応 | 後続。最初のpassではcopy自体を残す |
| 未使用命令の除去 | 未使用でも停止・出力・確保・解放が起きる操作の分類 | 後続。値の未使用だけを根拠に削除しない |
| 分岐・CFGの簡約 | 短絡、到達性、辺の引数、除去blockと出自の記録 | 後続。定数条件でも分岐を残す |

既存の `const` はfrontendで要求された定数式を評価する言語機能です。このpassは型・意味が確定した実行時IRへの任意の最適化であり、実行時の失敗をコンパイルエラーへ変更しません。

## 最初に変えるもの

適用範囲は言語の制限ではありません。対象外の操作を含む有効なSSAも受け取り、その操作をそのまま残します。

| 入力 | v1の扱い |
| --- | --- |
| 全8整数型・boolのliteral | ブロック内の既知値として登録。幅と符号を保持 |
| 既知値のscalar Copy | 命令を残し、行き先にも同じ既知値を記録 |
| 整数の加算・減算・乗算 | 両辺が既知で、同じ整数型として成功するときだけliteralへ置換 |
| 整数の6比較、boolの等値・非等値 | 両辺が既知なら結果のbool literalへ置換 |
| 関数引数・block引数・別blockの定義 | 未知として扱う。合流・loop・呼出し間の定数伝播はしない |
| 単項演算、除算・剰余、bit演算、数値変換、float | 演算を残す。v1では結果を既知値にしない |
| call・出力・文字列・複合値・残存slot・heap操作 | そのまま実行する。値や効果を最適化中に評価しない |

各関数の各blockについて、空の既知値表から命令順に一度だけ処理します。値がブロックの外で定義されていれば、その値がliteralでもv1では未知です。CFGの巡回順や不動点計算を結果の条件にしません。loopを静的に実行せず、blockを訪れるたびに成り立つ局所的な置換だけを行います。

演算は `runtime::value::binary` の既存の型付きscalar値を通して評価する方針です。IR・MIR・SSAの演算規則を再実装しません。許可する演算・型を先に絞り、整数とbool以外の値を渡しません。演算が言語上の失敗を返したら元命令を保ちます。不正な型など処理系内部の不整合はpassのエラーとして報告し、「畳み込めなかった」と同一視しません。

## 保持する意味と表現

正常終了時の出力バイト・戻り値、失敗コード・NodeId／SourceId／Span・停止前出力、評価順・短絡・所有・heap予算を保持します。floatの演算、NaN、負のゼロには触れません。

最初のpassには次の制約を置きます。

- 成功が確定した対象演算だけを、その場のliteralへ置換する。
- 命令数・命令順・ValueId・元InstructionId・Origin・型を維持する。
- 定数の入力命令・Copyも削除しない。分岐・辺・block引数・未到達記録を変更しない。
- 入力SSAと、その `original` にある非SSA MIRを変更しない。
- 対象演算でも失敗が分かる場合は元命令を残す。先行出力を消さず、実行された場合だけ元の位置で停止する。

次は説明用の略記です。現在の生成物や確定したテキスト文法ではありません。

```text
before: v0 = u8 6; v1 = u8 7; v2 = mul v0 v1 [mir-i2, origin=P]
after:  v0 = u8 6; v1 = u8 7; v2 = u8 42    [mir-i2, origin=P]
```

`u8 255 + 1` は成功しないため加算のままです。`x * 0` のxが未知なら置換しません。結果が未使用の加算も停止し得るため削除しません。`false && would_overflow()` の呼出しを最適化中に実行せず、生成済みの短絡CFGを保ちます。

現在のSSA検証器は、入力MIRとの命令数・ID・Originの対応を要求します。このv1はその制約を保てるため、最適化のために検証器を弱める必要はありません。ただし構造検証の成功は意味保存の証明ではなく、以下の実行比較・証明を別に要求します。

## 変換過程の観測

非最適化MIR、SSA変換直後、pass適用後、SSAから戻したMIRを別々に持ちます。同じファイルを「現在のIR」として上書きしません。

```text
HIR → 基準MIR ───────────────────────────→ 基準Native
       └ SSA前 → ssa-const-fold-v1 → SSA後 → 変換後MIR → Native
```

passのAPIは、検証済み入力を借用し、変換後SSAと置換記録を返す小さな構成を基本とします。最初から汎用のpass managerを導入しません。記録はテキストだけでなく構造化して持ち、表示とbundleが同じ記録を利用します。具体的なRust型・公開コマンドは実装時に確定します。

記録には次を含めます。

| 記録 | 内容 |
| --- | --- |
| pass | 名前 `ssa-const-fold-v1`、版、オプション、適用順、入力／出力snapshot |
| 置換 | 関数、SSA block、元MIR block、元InstructionId、ValueId、型、単一の停止出自 |
| 根拠 | 元操作とoperand番号、既知値の型・値・その値を得た命令／Copyの列、置換後literal |
| 結果 | 置換数。0件でも「指定されたが変更なし」としてpassを記録 |

保持する全命令は前後snapshotから比較できます。v1で省略した演算、未知のoperand、言語上の失敗により置換しなかった操作を、削除された命令として記録しません。詳細な非適用理由一覧は後続で検討します。

CLIは明示したpassだけを実行し、`--ssa` 単独では最適化しない方針です。未知のpass名や未対応の経路は診断し、黙って無視しません。暗黙の繰返しや追加passは入れません。最初のCLIではv1を一度だけ選べる形とし、複数passの順序・重複指定の扱いは拡張時に定義します。

bundleの最適化指定時は新しいschemaで、SSA前後・pass記録・対応表・そのSSAから得たMIR／ASMを追加し、各成果物の入力をmanifestに明示します。従来のv1（非SSA）とv3（SSAのみ）は維持します。具体的なフラグ名・ファイル名・schema番号は未確定で、現行CLIには追加しません。

## 実行例と検証条件

確認用の例は現在の言語機能だけで実行できます。まだ最適化後の出力を生成する例ではありません。

| 例 | 確認する意味 | 基準結果 |
| --- | --- | --- |
| [constant_candidates.ceru](../../examples/ir_stages/constant_candidates.ceru) | u8の乗算、u64最大値、定数比較、短絡、出力する関数の順番、loopの更新 | `42 / 18446744073709551615 / true / false / true / 4 / 10 / 7`の8行 |
| [constant_overflow.ceru](../../examples/runtime_failures/constant_overflow.ceru) | 未使用結果でもchecked加算を実行し、先行出力と停止出自を保つ | `7`の後に `limit + 1` で `integer-overflow`。99は出力しない |

現在の基準はIR・MIR・SSA・SSAから戻したMIR・VMで比較し、NativeのASM／Objectとも照合します。最適化の実装時には次の条件を追加します。

1. 全8整数型の境界、u64の大きな乗算、中間値のoverflow、bool比較を単体で検査する。
2. 入力不変、決定性、二度適用しても同じIRであること、ID・Origin・命令順・辺の不変、置換記録の再検査を行う。二度目の置換記録が0件になることと、pass自体の未実行は区別する。
3. 既存example・失敗例・heap予算を、元MIR／SSA前後／変換後MIR／VM／Nativeで比較する。call・float・所有操作が残ることも確認する。
4. Leanの独立したSSAモデルで具体例のpass前後と完了を検証する。少なくともu8の成功加算・overflowを含め、型・値・出自の誤った置換を拒否する。現在のLean exporterは乗算等に未対応なので、対象を明記して拡張する。
5. CLI／bundleでは既定出力の不変、明示passの記録、生成物の入力の区別を検査する。実行比較と有限例の証明を、全型・全変換器の証明に拡大しない。

## 再開時の実装単位

**実装は当面保留します。** [ロードマップ](language-roadmap.ja.md)に沿って、言語機能・入出力・完成成果物を優先します。設計と基準exampleは維持し、最適化を機能追加の前提にしません。

再開時は設計を基準に、まずRust APIのpass・置換記録・テストを追加し、次にCLI／bundleとNativeへの接続、有限例のLean検証へ進みます。未使用命令の削除・CFG簡約・block間の定数伝播は別pass／別版として扱います。元の演算や分岐を保存したまま、どの置換を行ったか追えることを完了条件にします。
