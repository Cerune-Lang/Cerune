# 完成した入力行の余剰容量を減らす

[English](input-compaction.en.md)

[容量の測定](input-memory.ja.md)を基に、Rustの4実行器とC・LLVM・QBE・Nativeで、完成後の文字列領域を縮小します。入力前に上限分を確保する手順と、文字列長を数えるメモリ上限は維持します。

## 適用条件

UTF-8検査が成功した空でない行について、次の両方を満たす場合だけ縮小を試します。

- 行の長さが指定上限の半分以下。
- 指定上限と行の長さの差が4096バイト以上。

これは小さな余剰のためにコピーやallocator呼出しを増やさないための実装上の方針です。文字列の意味や利用者向けの上限を変える条件ではありません。

| 場面 | 処理 |
| --- | --- |
| 読取り前 | 行の上限分の領域・使用バイト数・所有情報を予約。失敗なら入力を消費しない |
| 行の完成後 | UTF-8検査後、所有者を公開する前に縮小を試す |
| 縮小成功 | 小さな領域を完成文字列として渡す |
| 縮小失敗 | 元の領域をそのまま渡す。診断・再読取り・暗黙の再試行を追加しない |
| EOF・入力失敗 | 従来の解放・消費数・停止理由・NodeId/Spanを維持 |

## 経路ごとの実装

Rustは失敗を返せるtry_reserve_exactで実長分を確保し、本文をコピーします。失敗時は元のStringを保持します。所有情報は入力前に準備済みなので、所有登録のための追加確保はありません。

C・LLVM・QBE・Nativeは、所有管理領域を含めてreallocを試します。成功した場合は新しいアドレスで所有情報を初期化して登録し、失敗した場合は元のアドレスを使います。所有リストへ登録する前なので、移動前のポインタを他の値が保持しません。生成C・LLVM・QBE・ASMで条件・realloc・選択を確認でき、自前Objectにも同じ処理を符号化します。

**WATは既存の空き領域再利用を維持します。** [分割・再結合の比較](wat-input-storage.ja.md)では、分割だけでページ数が増え、再結合を加えても現行より減らせませんでした。この試作は製品へ導入しない判断です。文字列の意味、使用バイト数、入力・出力・診断は他経路と同じです。保持容量は共通の言語値ではありません。

## 保証の範囲

縮小を観測・制御する公開APIは追加しません。入力イベント・消費バイト数・読取り回数は変えず、観測の有無で縮小方針を変えません。テストの失敗注入・メモリ計測はテスト用の接続と生成物に限定します。

縮小成功後も、次の読取りには指定上限分の予約が必要です。縮小の失敗やallocatorの実装によって容量が残るため、プロセスのメモリ使用量を厳密に制限する機能ではありません。Rustのコピーやrealloc内の一時メモリも、文字列長とは区別します。

## 検証

- 4096バイト差と半分の条件について、成立する値と直前・直後の値を確認。
- Rustで縮小失敗を模擬し、本文・入力イベント・EOF・最初の失敗が同じことを確認。
- C/LLVM/QBEとMIR/SSA由来のASM/Objectで、通常・必ず縮小失敗・必ず移動する場合を比較。日本語・NUL・CR/LF、本文の保持、出力、最後の解放を確認。
- [2行保持のexample](../../examples/stdin/retained_lines.ceru)で、次の入力・改行なし最終行・EOF・後続の不正UTF-8を全経路で比較。
- WATの使用中容量・空き容量・ページ数が従来どおり再利用されることを確認。

2バイト×8本・1 MiB上限の測定では、縮小成功時の本文容量はRustで合計16バイト、malloc系では所有管理込み208バイトです。malloc系の確保要求のピークは1,048,782バイト。失敗を強制した場合は元の8,388,800バイトを保持したまま同じ結果を返し、全解放後はどちらも0になります。
