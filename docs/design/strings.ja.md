# 文字列の設計

[English](strings.en.md)

## 値の意味

`string`は不変なUTF-8の値です。`mut`な束縛への再代入は、保存していた文字列そのものを書き換える操作ではありません。コピー済みの値や、関数に渡した値は変化しません。

比較は内容全体で行い、Unicodeの正規化や大文字・小文字の変換はしません。途中のNULも内容の一部です。構文と演算の規則は[言語リファレンス](../reference/language.ja.md#文字列)に記載します。

## 観測と表現

| 段階 | 現在の表現 |
| --- | --- |
| Cerune IR | `string`型と解釈済みの文字列。元の引用符付き表記はSpanで追える |
| Bytecode | `push.string`、文字列型の保存・比較・出力命令。ソース由来の命令はNodeIdとSpanを保持する |
| VM | 不変内容の共有ハンドル。動的領域の論理的な保持・解放を別途管理する |
| C | 読み取り専用データの場所と、UTF-8のバイト数を持つ構造体 |
| LLVM | `%cerune.string = type { ptr, i64 }`と、静的／動的なバイト列 |
| QBE | 8バイトの長さとUTF-8データを持つ不変内容への64ビット参照 |
| WAT | 非公開のlinear memory内に置いた長さ付きデータへの32ビット参照 |
| Windows/Linux x86-64直接アセンブリ | 不変な内容への参照をレジスタ・スタックスロットで保持 |

IRとbytecodeのテキスト表示は、改行や制御文字をエスケープします。`print`は内容をそのまま出力します。表示の都合で値を変更しません。

共通の意味はCerune IRで確定し、格納・コピー・命令・呼び出し規約の選択は各lowererの内側で行います。EmitterはバックエンドIRから成果物を生成し、Ceruneの型や意味を再解釈しません。表現を一種類に揃えることより、それぞれの変換と理由を観測できることを重視します。観測境界は既存の`emit-ir`と出力成果物のままです。

## Cでの保存期間

```c
typedef struct cerune_string {
    const unsigned char *data;
    size_t length;
} cerune_string;
```

静的文字列はソースのリテラルまたはコンパイル時評価から作られます。データはCの文字列リテラルとして出力し、実行終了まで保持します。関数から文字列や文字列入りの配列を返しても、参照先は失われません。

代入では保存場所とバイト数をコピーします。データ自体を共有しても、Ceruneにはその中身を書き換える操作がないため、値の不変性を保てます。共有の有無やアドレスではなく、内容で等値比較します。静的文字列には保持・解放を行わず、`concat`の結果は`malloc`・`free`と参照カウントで管理します。

実行時の連結・予算・保持・解放は[動的データの設計](dynamic-data.ja.md)に記載します。共通IRが寿命を展開し、各生成先が領域を管理します。

外部入力は未実装です。生成Cの構造体を外部連携用の安定したABIとして定めるものではありません。

## バイト列と評価順

リテラルの各バイトは固定3桁の8進エスケープで出力します。Cコンパイラの文字コード設定に日本語の解釈を任せず、引用符などがCコードとして解釈されることも防ぎます。

等値比較はバイト数を確認してから`memcmp`で行います。表示は長さ付きデータとLFを、要求/受理数と出自を保持する[書込み処理](standard-io.ja.md)へ渡します。`strlen`や`strcmp`は使いません。Windowsでは数値だけの出力もバイナリモードにし、CR・LF・NULを保ちます。

Cが評価順を保証しない式に複数の作用や失敗し得る処理がある場合は、関数内の一時変数へソース順に保存します。短絡評価の右辺やループの条件・更新から評価を外へ移しません。束縛名にはCerune IRのIDも含め、同名変数や補助関数との衝突を避けます。

## LLVMでの表現とターゲット

LLVMでも静的文字列の内容は実行終了まで保持する定数です。各リテラルを`private unnamed_addr constant [N x i8]`へlowering時の出現順に保存し、UTF-8の各バイトを固定2桁の16進エスケープで出力します。終端NULは追加せず、元のバイト数を`i64`で保持します。空文字列ではデータを読みません。

文字列、文字列入りの積型、入れ子配列はLLVMの集約値としてコピーし、関数の引数・戻り値にも同じ表現を使います。確定済みの内容は書き換えません。動的文字列は既存の値表現を保ち、内部リストで所有領域を識別します。共有や最適化によるリテラル統合に関係なく、長さと全バイトで等値比較します。この内部表現は外部C ABIとの互換性を保証しません。

表示は長さ付きデータとLFを、[出自付きの書込み処理](standard-io.ja.md)へ渡します。数値・真偽値・引用表示も同じ接続を使い、順序・要求/受理バイト数・停止位置を保ちます。比較、短い書込み、割込みの再試行は生成LLVM上で読めます。

文字列を使う場合や標準出力を行うLLVM出力には`--target`を必須とします。現在の指定は次の2種類です。

| ターゲット | 標準出力の初期化 |
| --- | --- |
| `x86_64-unknown-linux-gnu` | モード変更なし |
| `x86_64-pc-windows-msvc` | CRTの標準出力（記述子1）に`_setmode(1, 32768)`を実行し、バイナリモードにする |

Windowsの初期化は、明示的な`main`の呼び出しも含めて最初のCerune処理より前に行います。失敗時は終了コード1で停止します。数値・真偽値だけでも末尾はLFです。検査付き演算・変換・添字だけを使う場合も[実行時診断](runtime-diagnostics.ja.md)の出力ABIを選ぶためターゲットを指定します。

指定は生成物の`target triple`に残します。コンパイラのホストOSや環境変数から選びません。未使用の定義も含めて文字列があるのに指定がなければ、ソース位置付きで診断します。下流のClangにも同じターゲットを渡してください。異なるターゲットへの上書きは、生成済みのOS依存処理を変換しません。

LLVM loweringは式をソース順に命令化し、短絡評価やループの内側に必要な分岐を残します。ターゲット指定は生成条件を選ぶデータであり、外部プログラムの起動やコンパイラへの干渉を許可するものではありません。

根拠となる仕様は[LLVMの定数表現](https://www.llvm.org/docs/LangRef.html#constants)、[target triple](https://www.llvm.org/docs/LangRef.html#target-triple)、[Microsoft CRTの_setmode](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/setmode?view=msvc-170)です。

## QBE・WAT・直接アセンブリでの保存と受け渡し

この3経路では、リテラルごとに「8バイトの長さ＋元のUTF-8バイト列」を静的に配置し、その先頭への参照を文字列値として保持します。関数の引数・戻り値、積型のフィールド、配列の要素も同じ参照です。長さも内容も実行中に書き換えず、終端NULを追加しません。文字列同士の共有・統合をCeruneが暗黙に最適化することもありません。

再代入は変数や配列要素が持つ参照の置き換えです。共有する参照先が不変なので、以前のコピーは変わりません。積型・配列自体のコピーには既存の`blit`、メモリのload/store、スタックスロットのコピーを使います。動的文字列の保持・解放は共通IRから生成し、静的領域には作用しません。この実装上の参照はCeruneのポインタ型や外部ABIを追加するものではありません。

QBEは静的データをLinuxでは`.rodata`、Windowsでは`.rdata`の読み取り専用領域に置き、`loadl`で長さ、`loadub`で各バイトを読みます。文字列・標準出力では明示ターゲットが必須です。Linuxの`x86_64-unknown-linux-gnu`には`qbe -t amd64_sysv`、Windowsの`x86_64-pc-windows-msvc`には`qbe -t amd64_win`を対応させ、生成物のコメントにも残します。Windowsでは最初のCerune操作の前にstdout/stderrをバイナリモードにし、初期化失敗時は終了コード1で止めます。数値だけでも明示WindowsターゲットではLFを出力します。後続QBEのターゲットだけを変えてもCerune側の実行環境は変換されません。

QBEの表示も[出自付きの書込み処理](standard-io.ja.md)を使います。要求/受理数、短い書込み、割込みの再試行、失敗時の停止を生成ILに残し、引用表示は固定256バイト領域から送ります。

直接アセンブリはWindows/Linux x86-64ターゲットを選べます。以下のWindows初期化に対し、Linux版はSysV規約でバイト出力し、標準出力モードの切替は行いません。静的な長さとデータは読み取り専用領域へ置き、参照は`RAX`や8バイトのスタックスロットで運びます。比較時には左辺を退避してから右辺を評価し、補助関数へ渡します。出力の補助関数はWindows x64のshadow space・スタック境界・保存レジスタの規則を守ります。数値だけの出力でも、最初のCerune処理より前に`_setmode`を実行し、失敗時は終了コード1で停止します。表示は[出自付きの書込み処理](standard-io.ja.md)を使い、ASMと自前Objectで要求/受理数・再試行・停止を揃えます。

WATではデータを非公開のlinear memoryに置き、32ビットのアドレスで参照します。8バイトの長さヘッダはリトルエンディアンで、現在のwasm32の処理は下位32ビットを読みます。静的領域と初期ページ数はlowering時に決定します。動的文字列は非公開領域を再利用し、必要時のメモリ拡張も失敗を検査します。等値比較は`i32.load8_u`と分岐に変換します。

### WATの出力と外部との境界

文字列を使うWATは`cerune.write_byte(i32) -> void`をimportします。生成コードが内容の各バイトを読み出して0〜255の値として渡し、最後にLF（10）を渡します。ホストは渡されたバイトを順番どおりに保持し、文字コード変換や改行変換を挟まない契約です。数値と真偽値の整形には既存の`print_i64`・`print_u64`・`print_f32`・`print_f64`・`print_bool`契約を使います。

複合値内の文字列は引用・エスケープし、数値は改行なしのホスト関数へ渡します。[複合値の表示契約](aggregate-values.ja.md)を参照してください。単独の文字列表示の規則は変わりません。

出力のためにmemoryをexport/importしません。ホストへ文字列の参照先を渡さず、読み出したバイト値だけを渡すため、出力インターフェースから内容を書き換える窓口を増やしません。これは実行時の出力契約であり、コンパイラの観測APIや観測からの制御を追加するものではありません。

## 検証範囲

Cのスナップショットに加え、実際の生成Cを最適化あり・なしでコンパイルし、VMの出力とバイト単位で比較します。日本語、空文字列、NUL、改行、正規化しない比較、コピー、関数からの返却、入れ子配列、評価順、同名変数を検査します。メモリ検査にはAddressSanitizerとUndefinedBehaviorSanitizerも使います。

LLVMのスナップショットはLinuxターゲットを明示して固定します。`cargo test --test llvm_strings`はWindows/Linuxの対応ホスト上で、生成LLVM・生成C・VMと既知の期待値を最適化なし・`-O2`で比較します。CR/LFを正規化せず、関数返却、積型、入れ子配列、コピー、評価順、短絡評価、範囲外アクセスも検証します。`CERUNE_TEST_LLVM_CLANG`と`CERUNE_TEST_CC`を指定するとコンパイラ不足を失敗にし、CIでは両OSで比較を必須とします。未指定で既定コンパイラがなければ理由を表示して実行比較をスキップします。

`string-values`の観測fixtureは全8成果物を固定します。`tests/support/string_cases.rs`の共通入力と既知の期待値を、VM・C・LLVMに加え、`cargo test --test string_routes`でQBE・WAT・直接アセンブリでも検証します。出力バイトの一致、評価順、短絡評価、コピー後の独立性、範囲外アクセスでの停止を分けて確認します。未使用の既定値にだけ文字列がある場合も、WindowsのC・LLVM・ASMが同じ出力モードを選びます。

QBEとASMはWindows x64とLinux x86-64で実行します。QBEのWindows比較は専用の`qbe_windows`テストで行い、生成段階ごとの表現を保存します。WATはWABTで検証・変換してNodeのWebAssemblyエンジンで実行し、公開要素が`main`だけであることも検査します。テスト用ホストの浮動小数点出力は共通fixtureで正確に表せる値`1.5`・`2`・`2.5`・`4`に限定しており、一般的な数値整形実装ではありません。実行できない経路は理由を表示し、成功した比較とは区別します。CIでは両OSのジョブを合わせて全経路の実行を必須にします。

開発用ツールは`CERUNE_TEST_QBE`、`CERUNE_TEST_ASM_CLANG`、`CERUNE_TEST_NODE`、`CERUNE_TEST_WAT2WASM_JS`（WABTの`bin/wat2wasm`）で明示できます。指定したツールがない場合はテスト失敗です。WABTの導入例は`npm install --prefix target/wasm-tools --no-audit --no-fund wabt@1.0.39`です。ツールの起動は開発用テストの責務で、Ceruneの生成コマンドには追加しません。

## バイト数を読む

`byte_len(value) -> i64`は保持済みのUTF-8バイト数を読みます。内容を走査・正規化せず、動的確保もしません。静的・動的の両方を扱い、対応する32/64ビット環境で表現可能な長さは`i64`の範囲内です。

フロントエンドで引数の型・個数と戻り値を確定し、Cerune IRには専用の`StringByteLength`を残します。通常の式では、リテラルの長さでもCerune内で定数へ折り畳まず、操作を観測できます。明示的なconstではコンパイル時に評価し、定義式と結果をIRに残します。表記は`byte_len.string(...)`、bytecodeは`byte_len.string`命令です。各lowererは次の読み出しへ変換します。

| 経路 | 長さの取り出し |
| --- | --- |
| VM | 型を検査して所有する文字列のバイト数を読む |
| C | 構造体の`length`を読み、`int64_t`へ変換 |
| LLVM | `extractvalue %cerune.string ..., 1` |
| QBE | 長さヘッダを`loadl`で読む |
| WAT | 非公開メモリの長さヘッダを`i64.load`で読む |
| Windows/Linux x86-64 ASM | `movq (%rax), %rax`で長さヘッダを読む |

長さを読む前に引数を一度評価します。Cでも引数にある呼び出しや失敗し得る式を評価順の処理へ伝え、複数の`byte_len`を組み合わせてもソース順を保ちます。LLVMの出自注釈からは`extractvalue`と元の`byte_len`式を対応付けられます。

`examples/string_byte_length.ceru`は日本語、NUL、CR/LF、合成済み・分解済みの文字列、関数返却、配列、既定値、再代入、短絡評価を実際に使います。全経路で既知の出力と比較し、`tests/fixtures/observation/string-byte-length/`には小さな入力と全8成果物を固定します。
