# 型・長さパラメーターを持つ関数

[English](generic-functions.en.md)

## 書き方

```cerune
fn first<T, const N: i64>(values: [T; N]) -> T {
    return values[0];
}
const COUNT: u8 = 2;
print(first::<string, COUNT>(["日本語", "予備"]));
```

| 指定 | 意味 |
| --- | --- |
| `T` | 型の仮引数。数値・bool・string・名前付き型・固定長配列を指定できる |
| `const N: i64` | 正の配列長の仮引数。型の`[T; N]`と本文のi64値として使える |
| `::<string, COUNT>` | 宣言順に全引数を明示。長さは接尾辞なしの正の整数リテラル、整数定数名、外側の長さ仮引数 |
| `pub fn` | 通常の公開関数と同じ。`alias::first::<T, N>(values)`で呼ぶ |

型引数の推論、既定の型引数、trait・制約構文、型自体のジェネリクス、再帰、関数の値化は今回の対象外です。長さは1〜i64の最大値で、配列として使う際には既存の格納量上限も適用します。任意の定数式は引数へ直接書かず、名前付き定数で計算します。

## 型検査と値の意味

仮引数名の重複、組み込み型名との衝突、同じスコープの型・関数・定数・import別名との衝突を禁止します。関数の値引数やローカル束縛で仮引数名を隠せません。型の仮引数を値に、長さの仮引数を型に使う場合も診断します。

型を指定すると、引数・戻り値・本文の型注釈を置換し、通常の関数と同じ規則で検査します。例えば`a + b`を含む関数はi64では使えても、連結を持たないstringではエラーです。数値変換に型仮引数を使う場合は`convert<T>(value)`と書きます。`T(value)`や`T { ... }`は型仮引数による構築構文として扱いません。

未使用のテンプレートから実行関数は作りません。構文・仮引数宣言は検査しますが、未使用本文の型検査完了を保証しません。モジュールの名前解決と公開範囲の検査は読み込み時に行います。呼び出しが短絡評価で実行されない場合でも、その具体化の型検査は行います。定数式からの関数呼び出し禁止も変わりません。

型・長さの引数はコンパイル時の情報です。通常の値引数は左から一度ずつ評価し、短絡で呼び出しを省く場合は評価しません。引数・戻り値は既存の値コピーで渡すため、配列や構造体を変更しても呼び出し元の値へ波及しません。文字列のバイト、不変性、正確な数値変換、異常停止の条件も維持します。

## 具体化と観測

共通フロントエンドで通常の型付き関数へ具体化し、その後に配列長解決、直和型の展開、型検査、Cerune IR生成を行います。VM・C・LLVM・QBE・WAT・Windows/Linux ASM・自前オブジェクトは、同じ具体化済みのIRを使います。

同じテンプレートと確定した型・長さの組み合わせは再利用します。`[i64; COUNT]`と`[i64; 2]`も、COUNTが2なら同一です。名前付き型はモジュールを含めた型の同一性を保ちます。内部関数名の`$generic_*`は利用者の識別子と衝突しません。生成先では使用できる文字へ変換し、関数IDで識別します。

```text
; instantiate first::<u64, 2> [definition source=0 bytes=0..72]
;   call [source=0 bytes=100..146]
;   call [source=0 bytes=185..209]
fn %$generic_0_first@0(%values@0: [u64; 2]) -> u64 {
  ...
}
```

IRには定義のSpan、具体化した引数、各呼び出しのSpanを保持します。構造化IRは型・長さ引数それぞれの記述位置も保持します。型引数の`[i64; COUNT]`も定数長の参照として残し、元のASTから型を問い合わせられます。本文の式のSpanは定義位置のままで、具体化ごとにNodeIdを割り当てます。型エラーには該当する具体化と呼び出し位置を補足します。同じ定義位置に複数の具体化がある場合は候補を併記します。実行時停止は元の本文の失敗式と停止前出力へ戻れます。これらは観測情報であり、実行中の値を書き換える権限ではありません。

再帰に対応します。解決済みの型・長さを本文の処理前に登録し、同じ組合せへの呼出しは処理中でも再利用します。本文は処理待ち一覧から登録順に具体化し、コンパイラの再帰callへ積みません。構造体の既定値からの呼出しも通常の実行時深さ検査を使います。展開は一回のコンパイルで256具体化・深さ64までです。未使用の型引数にも既存の型ごとの格納量制限を適用します。
