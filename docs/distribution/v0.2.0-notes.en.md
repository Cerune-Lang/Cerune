# Cerune v0.2.0 release notes

[日本語](v0.2.0-notes.ja.md)

[Cerune v0.2.0](https://github.com/Cerune-Lang/Cerune/releases/tag/v0.2.0) was published on 2026-11-17 from commit `481d325`. These notes cover changes since v0.1.0.

## Main additions

| Feature | What it provides | Try it |
| --- | --- | --- |
| Program arguments | `std:env` functions `arg_count` / `arg` expose count and values, including empty and missing arguments | [Argument listing](../../examples/arguments/README.en.md) |
| Integer parsing | `std:num::parse_i64` returns an enum containing a value, invalid format or out-of-range result | [Integer parsing](../../examples/integer_parsing/README.en.md), [seed arguments](../../examples/arguments/seed.ceru) |
| Binding syntax | Optional `let`, `value: = expression;` for ordinary bindings and for initializers, and `else if` | [Bindings and formatting](../../examples/formatting/README.en.md), [else if](../../examples/else_if.ceru) |
| Source formatting | `cerune fmt` displays, checks or explicitly saves formatted source; `--let preserve/show/hide` selects the let spelling | [fmt usage](../design/formatting.en.md) |
| Recursion | Direct and mutual recursion, including calls to the same generic specialization, with a shared call-depth limit | [Factorial, mutual recursion and owned values](../../examples/recursion/README.en.md) |
| File I/O | Bounded whole-file UTF-8 reads and new-file writes inside an explicitly selected working directory | [Write/read example](../../examples/files/README.en.md) |
| Subprocesses | Run registered executables without a shell; receive byte streams, exit status, failure and cleanup results as values | [Subprocess execution](../../examples/process_execution/README.en.md) |
| Native build/release | Link self-generated Objects using an explicit Clang driver; retain generated stages, origins and link records and package the program | [build](../design/native-build.en.md), [release](../design/native-release.en.md) |
| WAT function exports | Select public functions through the Rust API and generate checked JS calls and TypeScript declarations for i32/f64 | [WAT library](../design/wat-library.en.md), [browser example](../../experiments/host_calls/browser/README.en.md) |

Arguments, integer parsing, recursion, file I/O and subprocesses are supported through HIR, MIR, SSA, VM and generated C, LLVM, QBE, WAT and Native. Real OS file/subprocess connections target Windows/Linux; WAT uses versioned host imports. WAT function exports initially support i32/f64 arguments and results.

## Subprocesses and distribution

```text
Cerune source
  → construct a std:process Request
  → call run from std:process::run
  → shared runtime launches a registered executable
  → receive exit status, partial output, failure and cleanup in Outcome
  → continue the caller
```

Specify executables, working directories, environment values, capacity and time limits through `--process-config`. Nonzero exits and launch/transfer failures can be handled as result values. Without a connection, the result is `Unconfigured`. Failures such as insufficient storage for the result itself stop execution with a runtime diagnostic.

Link generated C, LLVM, QBE and Native with an explicitly specified static runtime. Linux also requires an absolute path to the supervisor executable. WAT can use the [reference host](../../experiments/wat_host/README.en.md).

Distribution now builds and tests extracted archives for five compiler targets and two runtime targets. Runtime archives include headers, licenses, a manifest and SHA-256 checksums. See the [tested OS table](release-readiness.en.md#tested-operating-systems).

## Upgrade checks

| Area | What to check |
| --- | --- |
| Call depth | Default 128; `--call-depth-limit` accepts 1–128. Source-function calls are checked after argument evaluation and before entry. Account for physical stack/memory use by large local values as well |
| LLVM/QBE generation | Specify `--target`, including for scalar-only programs |
| Large or deeply nested sources | [Syntax-depth and source-size limits](../design/frontend-limits.en.md) produce diagnostics when exceeded |
| Floating point | Generated C preserves rounding after each multiplication and addition. Cases previously affected by FMA contraction now agree with executors. Check the [supported external compiler settings](../design/float-rounding.en.md), including restrictions on fast-math |
| Formatting | `fmt` prints to stdout by default. Use `--write` or `-o` to save |
| Development-version subprocess imports | Replace `std:process/run` with `std:process::run`. Functions, types and runtime link requirements retain their existing behavior |

The subprocess import rename applies to development versions after v0.1.0. Current imports are:

```ceru
import "std:process" as types;
import "std:process::run" as process;
```

Use `types::Request`, `types::Outcome` and `process::run(request)`. Diagnostics and `emit-sources` also display the new module name. Regenerate compiled outputs and observation records with the version you use.

## Implementation and validation improvements

- Native instruction, data and Object generation now use a pinned SASHIMI commit. Instructions and origins passed by Cerune remain observable.
- Added comparisons of input storage and allocation failures across executors and generated routes.
- QBE 1.3 downloads are checked against a fixed SHA-256, with a verified alternate source when the primary distribution site is unavailable.
- Expanded Windows/Linux/macOS CI, archive execution tests and dependency checks. Development uses Rust 1.98.0 and Node.js 24.

## Try it

Run from the root of a source checkout containing these changes.

```sh
cargo run --quiet -- run examples/recursion/factorial.ceru
cargo run --quiet -- run examples/arguments/seed.ceru -- 1 3
cargo run --quiet -- run examples/process_execution/unconfigured.ceru
cargo run --quiet -- fmt examples/formatting/infer.ceru --let hide
```

Factorial prints `120` and `1`; the seed example prints `48271`, `182605794` and `1291394886`. The subprocess example prints the unconfigured result and `continued`. The final command displays formatted source.

## Further work

IR/VM Image save/load and build/release, independent LIR execution, general optimization, a full-language Lean backend, GPU and GUI remain on the [roadmap](../design/language-roadmap.en.md). File I/O covers reads and new-file writes. Runtime support for macOS, ARM64 and musl, and additional WAT export types and a dedicated CLI, remain future work.
